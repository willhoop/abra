## 1. ONE CAUSE OR TWO — THE QUESTION THE BRIEF ASKED FIRST

**TWO.** The evidence is structural and then measured.

| | C2 | C3 |
|---|---|---|
| the function | `redirectDrawnTo`'s two CALLERS | the attack branch's guard block |
| the wrong thing | the candidate ARRAY is `it.side==='A'?actB:actA` | the GUARD MAP is `it.side==='A'?field.sgB:field.sgA`, and the ally body is appended *after* the check |
| the authority's rule | `onAny…` is collected from every active body | a `TryHit` handler on a side condition fires for whichever TARGET is on that side |
| the predicate | `validTargetLoc` — adjacency, not side | `move.target ∈ {allAdjacent, allAdjacentFoes}` |
| shared code with the other | **none** | **none** |

**Measured rather than asserted.** C2 was landed alone and `tests/probe_ally_wide_guard.js` re-run
on the same tree: still `3 FAILED`, `allyGuardBlocked=0`. A single root would have closed both.

**What they DO share is a shape, and it is worth naming because it will recur:** in both places a
sentence in the source asserted the near side could not matter, and in both places no handler says
that. C3's was written out in full at the `_allyHit` site — *"the attacker's own side never raised it
against its own quake"* — and that sentence was the bug.

## 3. WHAT THE AUTHORITY ACTUALLY CHECKS

Champions overrides `abilities.ts` and `moves.ts`, and **neither `lightningrod` nor `wideguard` nor
`quickguard` appears in `data/mods/champions/`** — grepped, not recalled. So the mainline blocks are
the rule, and both were read whole.

**`lightningrod`:**
```js
onAnyRedirectTarget(target, source, source2, move) {
  if (move.type !== 'Electric' || move.flags['pledgecombo']) return;
  const redirectTarget = ['randomNormal','adjacentFoe'].includes(move.target) ? 'normal' : move.target;
  if (this.validTarget(this.effectState.target, source, redirectTarget)) { ... return this.effectState.target; }
}
```
and `validTargetLoc` (sim/battle.ts:2395), the clause that decides it:
```js
case 'randomNormal': case 'scripted': case 'normal':  return isAdjacent;   // NOT isFoe
case 'any':                                            return !isSelf;
```
In doubles a partner is adjacent and is not the user, so **all five members of `REDIRECTABLE_AIM`
admit it**, and the user's own slot is never adjacent to itself (`Math.abs(targetLoc-sourceLoc)===1`
is 0), so a rod still cannot pull a move out of its own mouth.

**`wideguard.condition`:**
```js
onTryHitPriority: 4,
onTryHit(target, source, move) {
  if (move?.target !== 'allAdjacent' && move.target !== 'allAdjacentFoes') return;
  if (this.checkMoveBypassesProtect(move, source, target)) return;
  this.add('-activate', target, 'move: Wide Guard');
  ... return this.NOT_FAIL;
}
```
**There is no test of the source's side, in either guard.** `getMoveTargets` pushes
`adjacentAllies()` into an `allAdjacent` list FIRST (sim/pokemon.ts:809), so the partner is a genuine
target of its own side's move and the handler fires for it.

move.spreadHit = true;` is the FIRST line of `trySpreadMoveHit` (sim/battle-actions.ts:551) — above
the whole step list, and the guard is a step. A near-side check hoisted one line earlier would hand
the foes 33% more damage silently.
