# ROTOM v0 — the live client (Reg M-C bo3, local server only)

2026-09-24 · branch `worktree-agent-aea75574da660f13b` · SOLVER-PLAN §4 / M3 · **PRE-GATE** (the Reg M-C MEDICHAM gate is not open;
no win rate below is a result, and none is quoted).

## Verdict

ROTOM v0 plays full best-of-3 sets of `gen9championsvgc2026regmcbo3` on a local `--no-security` pokemon-showdown-mc with the
timer on. Across **41 sets / 90 games** (six runs, below): **0 timeouts, 0 invalid choices (0 server `[Invalid choice]`),
0 crashed sets, 0 uncaught exceptions**. The socket-kill drill (1 s and 25 s outages) and the process-kill drill (watchdog
restart) each recovered mid-game and finished the set. Under the real clock (no operator cap) the bank was run from 420 s
down to a 40 s floor over a 16-turn game without a timeout.

Two defects were found by the runs and fixed after them (details §5): a double-forced switch with one bench body had no
enumerated joint (the client fell to `/choose default`, which the server accepted — 14 times across the pre-fix runs), and
the world laid on the wrong first-turn counter for Fake Out. The post-fix confirmation run (c5, 5 sets) used no fallback.

## 4. Disconnect recovery

- **Socket kill, 1 s (drill0) and 25 s outage (d3), set 1 game 1 turn 3.** The client closes the socket, backs off (the drill
  holds reconnect for 25 s), logs in again, sends `/join` for every open battle (`rejoin`), the server replays the room
  (`|init|` + log → `reinit`, the public record rebuilt from scratch), re-sends the open request, and the client answers it.
  In d3 the turn-3 request was answered 25.1 s after the drop; the game and set finished normally. The server kept the game
  alive on its DC bank (`DC Timer Bank`), so no timeout and no forfeit.
- **Process kill (watchdog), drill0 set 2 game 1 turn 2 and d3 set 2 game 2 turn 2.** The process exits (code 3); the
  harness (acting as the watchdog) restarts it in 1.5 s; it re-reads its run state and series book (`reloaded: 1`), takes the
  lock again, logs in, joins the games listed in `|updatesearch|`, and answers the pending request (drill0: rqid 8, 515 ms
  after the rejoin). A rejoined room with no server clock line yet is answered by the prior (the bank is unknown after a
  restart); the next `Time left` line restores the search.
- Anomaly logged, not a failure: the first `Time left` line after the 25 s outage read `509.9` s of bank where the previous
  line read 419.9; the budget was still bounded by `byTurn`. Not investigated further.

## 6. Owed (v0 limits, stated rather than hidden)

- **World fidelity**: not laid on — PP, sleep/toxic counters, volatiles (Substitute, Taunt, Encore, confusion, Perish), my own
  Choice lock (the request then allows one move and the filter drops the rest — c5's remaining unmapped joints), the
  opponent's spreads (flat table, as in the arena). Legality is unaffected; search quality is.
- **XATU**: the back-pair posterior is used (worlds drawn from it: 673 in m20, 0 fallbacks to uniform); XATU's spread belief is
  switched off in the client (cost not measured live).
- **Preview**: CHOMP does not exist; the `miltank` preview is a CHOMP-lite stand-in (90 options, random-playout successive
  halving, opponent sampled from the series carry-over rates). The prior preview is the pool team's human bring.
- **Worker pool** (`solver/miltank/pool.js`) is not wired into the live client; searches are in-process (the XATU world
  wrapper is in-process only).
- **Ladder**: no `/search`, no daily/series cap, no kill-switch file, no per-series ε/arm/Elo fields — all M4 work, and a
  ladder launch needs Will's OK. The lock is per machine only (§9 Q9).
- **M3 exit test** (SOLVER-PLAN §3): 0 timeouts / 0 bank forfeits / disconnect drill — met locally; "p99 latency under
  X − margin" — p99 was under the budget on every run (max move 48.1 s against a 47 s budget + ~1 s engine overrun at the
  real clock; the server allowed 55 s). The ~1 s overrun of the search past its budget should be tightened in v1.
