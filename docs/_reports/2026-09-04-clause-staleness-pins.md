## 3. What was built

Generalised, not enumerated. Three layers, each with one implementation.

**`engine/engine_release.js`** — `STAMP_SHAPE` (the pin field names, declared once; `stamp()` builds
from it and `pin_guard.js` reads from it, so a rename moves producer and guard together);
`treeDigest()` extracted out of `cut()`; `liveStamp()`, the same five fields computed off the LIVE
tree, writing nothing. That last one is what `tests/test-engine-diff.js` was missing — it reads the
live tree ON PURPOSE (an instrument is not frozen, only the engine is), and had no way to name those
bytes without cutting a release it had not read from.

Verified equal to the frozen path on an unmoved tree:

```
liveStamp()      engine_release=8ad06030e129  cut=2026-09-04T01:08:54.834Z  source_digests=26
open().stamp()   engine_release=8ad06030e129
SAME ID: true
```

**`engine/steering.js`** — `vouches(block, {policy})`, the ONE-SIDED question: can this block
identify its own population? It is the single list of selectors (policy, the behaviour tables under
`empirical-click/v1`, the census digest under the coverage policy, `team_pool_digest`), and
`comparable()` now calls it per side instead of restating it. A selector added there tomorrow is
checked by every clause the same day with no clause edited. The two duplicated refusals inside
`comparable()` were collapsed into it.

**`engine/pin_guard.js`** (new) — `guard({name, file, artifact, need, curId, policy, rerun})` returns
either `null` or a withheld clause result (`ok:false, cannot_answer:true, withheld:true`,
`clauseExit` 2). It refuses on: no release pin at all; a pin naming another release; a pin with no
`source_digests` (an id is a claim, the digest set is the receipt); a population that
`steering.vouches` will not vouch for. It throws if a caller passes no `rerun` command — a withheld
figure with no route back is a hole, not a refusal. Nothing measured is in scope on any refusal path:
the function is handed the artifact and reads only its declarations and its `generated` stamp out of
it.

**The assembler door.** `medichamIsCorrect()` now runs its clause list through `PIN.audit()`. Every
clause must hand back a `pins` receipt naming the artifact it read and what it checked, or declare —
with a reason, enforced by a throw — that it reads no artifact. A clause with no receipt is withheld
whatever its own verdict said.

An earlier draft had `audit()` find an unreceipted clause's artifact by matching its `generated`
timestamp across `data/` (`coverage.clauseArtifact`). That returns null on an ambiguous match, so the
guard would have gone silent exactly where it could not tell — the silent default rebuilt inside the
thing built to stop it. There is no inference step now: declare or be withheld.

**Producers, so the regeneration is one pass and not two:**
`tests/test-engine-diff.js` spreads `liveStamp()`; `tests/roster.js` spreads `REL.stamp()` in place
of `engine_release: REL.id`; `engine/all_mechanics_fire.js` spreads `GD.REL.stamp()` and keeps
`release` beside it for readers that cite it by that name.

**`engine/sweep.js`** — two repairs, both caused by this change and both real. `stampKeys()` parsed
`stamp()`'s SOURCE for its key names and went blind the moment `stamp()` was rewritten to build from
`STAMP_SHAPE`; it now imports and keeps the parser as a fallback. And §2's "is the pin READ?" test
was a grep over the producing function's text, which cannot follow a delegation — it accused
`wholeGameClause` of not reading the team pool through two module hops. It now reads the clause's own
`pins.checked` receipt when there is one, and flags a clause with NO receipt as the loudest row.

## 4. Red first, then green — per clause

25 new selftest arms in `engine/quarantine.js --selftest`, each driving the SHIPPING function.
`PIN GUARD / RED` feeds an absent or wrong stamp and asserts a refusal; `PIN GUARD / GREEN` feeds a
correct one and asserts the clause answers. Without the second arm the change is indistinguishable
from a permanently red gate, which is the point of having them.

Covered: differential (no pin / wrong release / id-without-digests / good); roster (no stamp / good);
mechanics (hand-rolled `release` / no pin / good); whole-game (right policy with no
`team_pool_digest` — **the reported defect itself** / no steering block / wrong policy naming both
policies / good); the assembler door (unreceipted clause refused, receipted clause passes through,
artifact-free clause with a reason passes, artifact-free clause with NO reason throws); `clauseExit`
= 2 on every refusal; and a `PIN_COUNTERS` arm so the guard can prove it ran rather than returning a
canned answer.

Three arms assert **no figure comes back with the refusal**. One of them caught a real leak in my own
first draft: the whole-game re-run string carried a bracketed aside, and
`tests/test-divergence-composition.js` — which reads a `[...]` block back out of `why` as the shape
composition — parsed it as an empty composition sitting beside a refusal. A bracketed aside is
indistinguishable from a figure to anything that greps. It is now plain prose in a `note` field.

**Two existing arms were INVERTED, and both would otherwise have gone on passing while asserting
nothing** — the green-test-asking-nothing failure. `#316 — an UNSTAMPED roster artifact is allowed to
answer` and `#298 — an UNSTAMPED artifact is allowed to answer` both build their fixture from a
helper that now supplies a pin, so they would have kept passing against a fixture that is no longer
unstamped. They now strip the pin explicitly and assert the refusal. A third, in the order probe —
*"the withheld run still reports what it found, so the figure is visible and unquotable"* — was
inverted too: there is no such thing as a visible unquotable figure here.

**The one regression, caught and fixed.** `tests/test-divergence-composition.js` was GREEN before and
went to **11 CHECK(S) FAILED** after — measured by stashing `quarantine.js` and `steering.js` and
re-running. Same shape as last night: its synthetic arms declare less than a real artifact does. The
FIXTURE was fixed (release pin + full steering block, both derived from `STAMP_SHAPE` and
`steering.js` rather than typed) and two new control arms added for the two new refusals, byte-
identical to `ARM_A` but for the one field, so the knob is varied and the outcomes differ. Back to
`all checks passed`.

## 6. Will's acceptance test: a second instance, spelled differently, through another door?

**Inside `medichamIsCorrect()`: yes, structurally.** A fourth clause added tomorrow reading a fourth
artifact with no pin at all **cannot pass**. It does not need to be known to `pin_guard.js`; it needs
to hand back a receipt, and a clause that reads a file without going through the guard has no receipt
to hand back. `PIN.audit` withholds it and the refusal names the two calls that fix it. That is
asserted by `PIN GUARD / RED — A FOURTH CLAUSE ADDED TOMORROW WITH NO PIN CANNOT PASS`.

**Outside that list: no, and this is the residual.** `orderProbeClause` was outside it, which is how
it kept the fifth copy of the sentence; I fixed the clause, but the fix is a fix and not a mechanism.
A SIXTH clause built outside `medichamIsCorrect()` is still only caught by somebody calling the
guard, or by `sweep.js` §2 — which derives it correctly and which nothing invokes (sweep is in its
own §1, the 59 checks no runner runs). Wiring sweep §2 into `tests/run-all.js` is the honest close
and it is not done here.

**Second residual, named rather than tuned away.** Sweep §2 still reports `NO POPULATION PIN` against
`all-mechanics-fire.json` and will keep doing so after the regeneration. Its `POP_RX` vocabulary
matches names like `pool` / `census` / `team_pool`, and this artifact's population is pinned under
`showdown_commit` and `source_digests` instead. Widening the regex to silence it would trade a false
positive for false negatives elsewhere. It is a limit of that instrument's vocabulary and is stated
here rather than removed.
