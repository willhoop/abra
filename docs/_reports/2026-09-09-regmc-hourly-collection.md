### Defects fixed in the gap detector

1. **False GAP on the catch-up run.** The store's `date` is minute-floored, so `newest_stored` sits up
   to 59 s before the true uploadtime of the newest stored game. A run whose oldest offered id IS that
   game read it as "newer than the store" — exactly the run where the window has just caught up.
   Observed on the scratch rerun: `newest_offered=20:47:13Z` vs `newest_stored=20:47:00Z`. The
   condition is now `held===0 && oldest>newestStored`: no shared id is the test of "no overlap"; the
   timestamp only fixes the direction and excludes the empty-store first run.
2. **The coverage line never reached CI on an all-held run.** `next_regulation_ingest.js` relays ONE
   stderr line — the last — as `ingest_said`. The block printed before the ZERO-GAIN / STALE-LADDER
   guards, so on an all-held run the last line was `nothing new: ...`. It is now `reportCoverage()`,
   called last in `main()`; a firing guard still exits first and keeps its own reason as the relayed
   line (the run is red then and the reason matters more).

Extractor and schema untouched (`tests/test-parse.js` 42/42). `--strict-gap` is parsed anywhere on
the line; the store is the first non-flag argument.

## 3. Hourly workflow — `.github/workflows/next-regulation.yml`

- `cron: '7 * * * *'` (offset from ingest.yml's `17 */6`), `workflow_dispatch`, `permissions: contents: write`.
- **How the two bots avoid clobbering each other:** (1) `concurrency: group: ingest` — the SAME group
  as `ingest.yml` (verified at its lines 20-22); GitHub concurrency groups are repository-wide, so the
  two jobs never run at once. (2) The commit step copies ingest.yml's pattern exactly: `abra-bot`
  identity, commit, then a 3-attempt loop of `git fetch` → `git reset --hard origin/main` →
  `--reconcile` (origin's `.gz` rows first, first id wins, refuses to shrink) → `--raw` → re-stage →
  commit on top of origin → `git push` (always a fast-forward). (3) Disjoint files anyway: stages
  only `data/next-regulation.json`, `data/games.gen9champions*.jsonl.gz` and
  `data/raw/games.gen9champions*/*.jsonl.gz`, walked as globs with `-e` guards; never `git add -A`.
- Automatic path `node engine/next_regulation_ingest.js` (verified locally to collect both
  candidates: 1399→1412, 721→727, artifact `mode: scheduled`) PLUS a dated belt-and-braces step
  `--format <id> --no-write` for both Reg M-C ids. `--format` idempotency confirmed by reading the
  code, not the header: reconcile → spawn `durable-ingest.js` (appends only ids not in the plain
  store) → reconcile. `--no-write` returns before the artifact write (`next_regulation_ingest.js:312`).
- GAP reaches the job log three ways: the relayed `ingest_said` line on both steps; the named step is
  tee'd to `$RUNNER_TEMP/named.log` (with `pipefail`) and the guard step re-emits any `GAP:` line as
  a `::warning::` run annotation; the automatic step's GAP is grepped out of the artifact.
- Validation: both workflows parse under js-yaml (`cron`, `permissions`, `concurrency` read back as
