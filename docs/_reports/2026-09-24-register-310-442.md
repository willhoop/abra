## #442: why it could not answer under Reg M-C

The probe forced the child's `SHOWDOWN_PATH` to the Reg M-B checkout, and read and compared the census as
`data/mechanics-census.json`. Under Reg M-C the census is written to `data/mechanics-census-regmc.json` (the artifact
seam in `engine/regulation.js`), so the probe read the temp tree's untouched Reg M-B copy, found the committed
timestamp and refused ("did not write a fresh census"). 47 s in the register log is consistent with the child refusing
early against the wrong authority.

**Fix** (`tests/probe_census_reproduces.js`): the census path is `REG.artifactFor('data/mechanics-census.json')`, both
for `git show HEAD:<path>` and for the temp tree; the child gets the checkout `showdown_path.js` resolved for the
selected regulation, and `ABRA_REGULATION` when a non-owner regulation is selected. It now also prints a class:
**OVERCLAIM** (a committed row the tree reads missing or no longer has, or a higher committed live count: the shape
#442 was filed for) or **UNDERCLAIM ONLY** (every committed row reproduces; the tree probes rows the committed census
lacks). Both stay RED.

**Reg M-C reading at `7c9f7534`**: committed `data/mechanics-census-regmc.json` live 1010 / probed 1010 / missing 0
(generated 2026-09-24T02:11:14Z); regenerated in 489 s, test-mechanics exit 0; identical. **GREEN.**
Control: `--plant` (flips row 0 of the regenerated census before the compare) — see the last section.
