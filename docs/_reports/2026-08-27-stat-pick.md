## 1. What produced it — derived, not assumed

`Dex.forFormat('gen9championsvgc2026regmb')`:

- `species.get('scovillain').abilities` = `{"0":"Chlorophyll","1":"Insomnia","H":"Moody"}`
- The probe does not name it. It derives the ability as *the one legal ability whose `onResidual`

- `onResidualOrder: 28`, `onResidualSubOrder: 2`.

**Champions does not override it.** `data/mods/champions/abilities.ts` was grepped in full for `moody`

## 2. How the authority picks — cited, whole block

`data/abilities.ts:2691-2722`:

- **TWO draws, not one.** `this.sample(stats)` appears twice.
- **Eligibility is filtered BEFORE each draw.** The `for (statPlus in pokemon.boosts)` loop builds a
  list of stats with `boosts[stat] < 6`, and `this.sample` is called on that list. Same for the drop
  with `> -6`.
- **The second draw excludes the first**: `statMinus !== randomStat`.
- `accuracy` and `evasion` are skipped in both loops.
- **Both lists are built before either boost is applied** — `this.boost(boost, ...)` is the last line.
- Draw order is the key order of `pokemon.boosts`: `atk, def, spa, spd, spe`.

`PRNG#sample` (`sim/prng.ts:132`) is `items[this.random(items.length)]` and `PRNG#random`
(`sim/prng.ts:91`) draws unconditionally — the draw is taken even for a one-item list.

**medicham2's handler matches every clause** (`engine/medicham2-browser.js:31288-31300`, WIRE 133):
same stat order `['at','df','sa','sd','sp']`, same `<6` / `>-6` gates, same `k!==_plus` exclusion,
both lists built before either `_apply`.

## 3. The address — and this is where it parts

The `middle` arm keys both engines on `seed|turn|category|move|target|nth`. At the residual the
authority has already run `clearActiveMove(true)`, so the move and target fields are `-|-` on **both**
sides. `nth` is a field of the address and therefore an input to the hash, so
`<seed>|<turn>|any|-|-|<nth>` is a **per-turn sequence wearing an address** — every non-action draw of
the turn shares it.

**CONTROL board** (`Ally Switch`, target `self`; `getRandomTarget` returns the user for that class and
takes no draw), 3 turns, both carriers, every residual with 5-of-5 and 4-of-4 eligible:

```
  authority  +spe2 -atk1 +spa2 -atk1 +def2 -spe1
  medicham   +spe2 -atk1 +spa2 -atk1 +def2 -spe1
  residual-bucket draws:  authority 6   medicham 6   (matched)      AGREE
```

**The handler is correct and the die is shared.** Not "unmeasurable", not "no shared address".

**CONTAMINATED board** (`Air Cutter`, target `allAdjacentFoes`), same carriers, same 5/4 eligibility:

```
  authority  +spa2 -atk1
  medicham   +spe2 -atk1
  residual-bucket draws:  authority 15   medicham 2   <-- nth is shifted by 13
```

Every authority draw in that bucket was attributed by stack, on the authority itself:

| count | origin |
|---|---|
| 57 | `PRNG.sample <- Battle.sample <- Side.randomFoe <- Battle.getRandomTarget` (from `BattleQueue.resolveAction`, `Battle.getActionSpeed`, `BattleActions.runMove`) |
| 28 | `PRNG.sample <- Battle.sample <- Battle.onResidual` — Moody's own two |

A spread/field move is used with no chosen target, so `Battle#getTarget` (`sim/battle.ts:2434`) falls
through to `getRandomTarget` (`:2487`), which in doubles ends at `pokemon.side.randomFoe()` →
`this.sample(actives)` — **up to three draws per click**. Measured per target class, one
representative move each, `-|-` draws authority vs medicham over 3 turns:

```
  normal / self / any / adjacentAlly / adjacentAllyOrSelf / allySide / all / allyTeam    2 vs 2
  allAdjacentFoes, allAdjacent, allies, randomNormal, foeSide                           13 vs 2
  scripted                                                                               4 vs 2
```

**medicham2 takes ZERO draws in that bucket other than Moody's two** — the full address dump for the
contaminated board shows 15 authority `-|-` entries and 2 medicham ones, with medicham's `acc`,
`dmg` and `crit` addresses matching the authority's exactly.

Searching all consecutive pairs 0..19: medicham's answer has a **unique** solution, `nth 1,2`. The
authority's has two, `nth 0,1` and `nth 6,7`. The adjacent reading — authority at 0,1 and medicham at
1,2, i.e. **medicham took ONE draw in that bucket the authority did not** — is the parsimonious one and

## THE PATCH, NOT APPLIED

Give the residual draw an address of its own, so it stops sharing a sequence with every other
non-action draw in the turn. Both engines already know the body; neither has to be told anything new.

**(a) `engine/game_differential.js`, `midDraw`, the `const ctx = midCtx([...])` line (~1137).**
When there is no `activeMove` and the battle is inside a residual, name it:

```
b.event && b.event.id === 'Residual' && b.event.target && b.event.target.side
  -> move field   'residual'
  -> target field b.event.target.side.id + b.event.target.position
```

**Printed before proposing it, on the contaminated board:** at Moody's two draws the authority carries
`event.id='Residual'`, `event.target='p20'`, `battle.effect.id='moody'`; at all thirteen random-target
draws `event.id=''` and `event.target` is `undefined`. The branch cannot over-match — the two
populations are disjoint on the authority's own fields.

**(b) `engine/medicham2-browser.js`, the residual group walk,
`for(const m of residualOrder(actA,actB,field))` at line 31229.** Set `MID_MOVE='residual'` and
`MID_TGT=midEventSlot(m)` at the top of the body and restore with the existing `midClearActiveMove()`
after the walk — the identical shape as `MID_TGT=midEventSlot(R.tg)` at line 30275. No handler moves;
WIRE 133 is untouched.

**Address by BODY, not by EFFECT, deliberately.** `battle.effect.id` is available and would isolate
Moody from Healer and Shed Skin as well — and that is exactly why it is the wrong choice. Those two
asymmetries are **real engine defects** (guard evaluated after the coin instead of before it) and
per-effect addressing would silence them while leaving them in the engine. Per-body removes the
cross-mechanic contamination and keeps the same-body ones measurable.

**What this does and does not fix.** It fixes row #7. It does **not** fix the random-target row
(p2 staraptor/incineroar HP swap, turn 2) or the two Trace rows — medicham2 modelling no random target
selection at all is a separate, board-material defect and keeps its own row. It removes their
contamination of the stat pick.

**Declared consequences.**
- It moves `PIN_DIGEST` / `DICE_MODEL`. A run before and a run after are two instruments, not two
  samples; `engine/arms_comparable.js` must refuse to table them together.
- It needs a knob (`MEDI_MID_RESIDUAL_ADDR=0`) restoring the old address, so the defect can be shown
  RED rather than asserted — same shape as `MEDI_ACTIVE_MOVE_STICKY` and `MEDI_MID_RANGE_DRAWS`.

**Which scoreboard should move.** Moody is 605 uses / 249 sheets and Scovillain is in the pinned pool
— this row came out of it. So **both**: the pool should lose one board-material game (9 → 8) and the
lab probe should go green. If the pool does not move, the fix did not reach the cause.
