# Living docs brought to 5.246.0 — a retraction pass, not a bump

2026-09-04. MEASURE. Documentation only: no game was played, no engine or measurement script was
run, nothing was committed. `docs/ENGINE.md`, `docs/ROADMAP.md` and `engine/medicham2-browser.js`
were not touched — other agents own them this session.

## What the pass was

`CHANGELOG.md` tops at 5.246.0 and six version-headed documents read 5.245.0, so
`tests/test-docs-current.js` clause 2 was red. The content behind the bump is mostly a RETRACTION,
which changes what the pass has to do: the six documents did not merely lag the changelog, **they
published a false claim about the engine hours earlier and four of them reasoned from it.**

## The claim that is withdrawn, and where it actually lived

5.245.0 states that *"every body in this engine that loses an item gets Unburden's speed doubling."*
Measured across `docs/*.md`, the claim was live in **all six version-headed targets plus
`docs/MEASURE.md`** — not the four the changelog note estimates. Each carried it inside its own
5.245.0 dated block:

| document | where | wording it used |
|---|---|---|
| `docs/ABRA-whitepaper.md` | `:5` (5.245.0 block) | *"every body in this engine that loses an item gets Unburden's speed doubling"* |
| `docs/ABRA-technical-docs.md` | `:5` | *"Every body that loses an item therefore gets the doubling."* |
| `docs/ABRA-deck-plain-english.md` | `:5` | *"our simulator gives that doubling to every Pokemon that loses an item, whether or not it has the ability"* |
| `docs/DAMAGE-STAGES.md` | `:5` | same sentence, as a second-order note about turn order |
| `docs/MODELS.md` | `:5` | *"every body that loses an item is given Unburden's speed doubling"* |
| `docs/SUMMARY.md` | `:17` (inside the 5.245.0 section) | *"every Pokemon that loses an item … is given Unburden's doubled Speed"* |
| `docs/MEASURE.md` | `:142-145` | an **OWED work-list bullet**: *"Unburden is an ENGINE defect … and needs a register row."* |

The first grep run for this pass under-counted, because five of the seven occurrences sit inside
single 3,000-character block paragraphs and a line-truncated `grep` output hid them. The counting was
redone with `grep -o` over a window. **A search that truncates its own output is the same class of
instrument error this pass is about**, and it is recorded here rather than quietly fixed.

## How each one was corrected

Two different treatments, deliberately:

- **Dated block → superseded from above, never rewritten.** The six version-headed documents each
  gained a new `**5.246.0 …**` block at the head of their stack that QUOTES the retracted sentence in
  the document's own wording and says it is withdrawn. The 5.245.0 text is left byte-identical where
  it was published, because a dated block is evidence.
- **Work-list bullet → corrected in place, with its old wording quoted.** `docs/MEASURE.md:142` was
  an OWED item claiming an engine defect that does not exist. A false open item sends someone to fix
  a non-defect, so the bullet itself now reads `RETRACTED 2026-09-04 (CHANGELOG 5.246.0)`, quotes
  what it used to say verbatim, and points at what replaced it. `docs/MEASURE.md` also gained a full
  dated retraction section directly under its `<!-- GENERATED -->` block.

## The mechanism, which is the part that had to be written down

Not *"this was wrong"* — the durable statement is why it was believed:

```
tests/probe_leaf_widening.js:277
const stand = m => (m && m._hadItem && !m.item) ? 1 : 0;   // the PROBE's own predicate
```

The probe reported `stand` as this engine's side and compared it against the authority's `unburden`
volatile. **It never read `effSpeed`.** An agreeing reading therefore asserted exactly one thing —
*both bodies had lost an item* — and could not have detected the multiplier, present or absent, in
either direction. An instrument that compares its own stand-in against the authority can only ever
confirm its own stand-in.

The engine's actual gate, per the changelog block and re-derived here where it could be derived:

- `engine/medicham2-browser.js:14770` is the ENTRY GUARD (`m._hadItem && !m.item`); the multiplier is
  pushed on the next line, `:14772`, gated on `TAGS.param('ability', m.ability, 'speedOnItemLoss')`.
  **Cited from the 5.246.0 changelog block, not re-read**: another agent owns that file and is
  editing it this session, so a live read could have returned a different line number than the
  record carries, and "one fact, one number, identical everywhere" is worth more here than a
  second-hand confirmation.
- **Derived this pass** by walking the ability block of `data/tags.json`: exactly one key carries
  `speedOnItemLoss`, and it is `unburden`. (`data/tags.json` is static and was not being written.)
- The census control already on record: `ability none 187,187` (the must-not-move arm) against
  `Unburden 187,374`.

Every document now carries the same general lesson in its own register: **an instrument can be wrong
before the engine is**, three times in one night — a probe printing `undefined<>undefined` as its
receipt, a selftest exercising a five-line copy of the rule it was checking, and this probe.

## The defect that survives

ROADMAP #535, carried into all eight documents so the correction cannot read as *nothing was wrong
here*: the doubling is recomputed from the body's CURRENT ability instead of being held as the
volatile the authority grants at the instant the item is lost, so an Unburden acquired AFTER the hand
empties doubles here and does not in the authority. Skill Swap is the reachable door. Filed
`INSTRUMENT OWED` — nothing in the tree decides it.
