## VERDICT IN ONE PARAGRAPH

The five rows are derived and landed, the forme instrument moved from **five UNCOVERABLE** to **six
judged rows**, and Disguise and Hunger Switch now AGREE with the authority on all four assertions.
The **link to the Morpeko divergence is REFUTED**, with a control: the divergence is byte-identical

## 1. THE PRIOR WALL, FOUND BEFORE ANYTHING WAS TOUCHED

`#204` records that `engine-data.js` was not regenerated because a previous agent hit a wall wiring
`formeFollowsWeather`. The wall is written into the engine, at `medicham2-browser.js:12248-12255`:

> *"IT IS MODELLED AS A RETYPE, NOT AS A FORME SWAP, AND THE REASON IS A FILE THIS DIVISION MAY NOT
> EDIT. `data/engine-data.js` holds a row for `castform` and NONE for Castform-Sunny, Castform-Rainy
> or Castform-Snowy, so `formeSwap` would fail its `buildMon` lookup, count `formeSwapNoRow` and
> change nothing — the mechanic would be 'wired' and inert."*

That agent was right about the constraint and its workaround is still in place. **The rows do not
undo it** — see §5.

## 2. THE BUILDER THAT OWNS THESE ROWS SKIPPED THEM, AND ITS STATED REASON IS FALSE FOR CASTFORM

`engine/merge_mega_into_engine.js` is the builder that adds non-mega forme rows. Its predicate:

```js
const bodyDiffers = !!(baseRow && f.base_stats &&
  JSON.stringify(baseRow.bs) !== JSON.stringify(f.base_stats));
const addableForme = !isMega && !MC.mons[key] && f.in_our_store && bodyDiffers;
```

and its comment: *"A forme whose stats **and types** match its base needs no row, because the fallback
already handles it exactly."*

All five formes are in `data/mega-dex-official.json` with `in_our_store: true`. All five have base
stats identical to their base, so `bodyDiffers` is false and all five are skipped. **For
Castform-Sunny/Rainy/Snowy the TYPES differ and the predicate never looks at types**, so the builder
skipped them for a reason its own comment says should not apply. That is the gap, named.

The source artifact independently corroborates every value derived here — `mega-dex-official.json`
agrees with `Dex.forFormat` on types and base stats for all five.

## 7. THE MORPEKO LINK: REFUTED, WITH THE REAL CAUSE

### The brief's premise was half right and the framing was wrong

Three of the 40 cards in `data/divergence-turns.json` mention Morpeko, not ten; one of them is the
switch case. And it is **not a switch-ORDER divergence**. Seed
`gen9championsvgc2026regmbbo3-2655542565`, `middle` arm, 54 lines agreed:

```
SHOWDOWN  |switch|p2b: Morpeko|Morpeko, L50|133/133
          |switch|p2a: Espathra|... |switch|p1a: Floette|... |switch|p1b: Sneasler|...
          |-formechange|p2b: Morpeko|Morpeko-Hangry|
MEDICHAM  |switch|p2a: Espathra|espathra, L50|170/170
          |switch|p1a: Floette|... |switch|p1b: Sneasler|...
```

medicham2 emits **no line at all** for p2b — that is why the class is `event missing from medicham2`
rather than `ordering`. Speed never entered into it, and neither did `comparePriority`,
`switchin_order.js` or `data/switchin-order.json` (those govern the order entry ABILITIES resolve in,
not which `|switch|` lines are emitted).

The same card's own roster dump carries the answer: a bench body named **`morpekohangry` with
`key: null`**.

### The refutation

`<scratch>/probe_switchback.js`, same board, run against both releases:

```
rows PRESENT   after the ask: medicham [espathra,dragonite]   authority [morpekohangry,dragonite]
rows EXCISED   after the ask: medicham [espathra,dragonite]   authority [morpekohangry,dragonite]
```

Byte-identical. **The forme rows are not the cause.**

### The two causes, either of which alone produces it

Staged as `tests/test-switch-back-renamed.js`. Subject and control on the same board, same turn, same
ask: Morpeko flips to Hangry, leaves, is asked back; Dragonite (never renamed) leaves and is asked
back beside it.

**C1 — ENGINE.** A NON-permanent forme change is not reverted when the body leaves the field. Measured
while the body is off the field:

```
bench ours [morpeko-hangry, dragonite]   authority [morpeko, dragonite]
```

Showdown's `Pokemon#formeChange` takes an `isPermanent` flag; Hunger Switch passes nothing, so
`clearVolatile` puts it back. medicham2 keeps the flipped name. Owner: `engine/medicham2-browser.js`.

**C2 — INSTRUMENT.** `engine/game_differential.js` stamps `_switchKey` in `buildPair` (:2213)
precisely so a rename cannot orphan a body — its own comment says *"THAT BODY CAN NEVER BE SWITCHED TO
AGAIN"*. But `freshBodies` (:2362), which is what every PLAYED game is built from, rebuilds through
`M.buildMon` and does not carry the stamp:

```
buildPair   _switchKey: ["morpeko","dragonite","espathra","garchomp"]
freshBodies _switchKey: [null,null,null,null]      <- what every played game uses
```

so the resolver falls through to `id(x.name)`, misses, and answers `pass`. One fact, two construction
paths, one of them fixed — CLAUDE.md's facts-are-global shape, arriving in the instrument.

**Sufficiency, proved without editing a file another agent is using:** putting the stamp back on the
bench bodies from `onBoundary`, one boundary before the ask, makes the subject return
(`medicham [morpeko,dragonite]`). The control returns on every arm on both engines.

### C3 — a third shape, and it is NOT the same

A MEGA is a PERMANENT rename, so **both** engines hold `abomasnow-mega` while the driver's ask still
says `abomasnow`. The Showdown branch matches on `id(q.species.id)` (:3436) and misses too, so the
game does not diverge quietly — it **throws**:

```
p1 choice rejected p1 "pass, switch 4": Can't pass: Your Espathra must make a move (or switch)
```

Restamping `_switchKey` does **not** clear it, which is what proves it is a different defect. The
over-fire control is decisive: the identical board asked as `{sw:'abomasnowmega'}` completes on both
engines with matching actives. Mega bodies are 26.1% of format usage; how often the differential
actually asks a mega'd body back in is **not measured here** and must not be inferred from that share.
