## 4. THE ONE ATTRIBUTION I COULD NOT CONFIRM — OPEN, NOT RECONCILED

The matched pinned pair (census pin, `data/team-pool-frozen`, arm `middle`, empirical steering, only
`--release` differing) read **777 games, 98 diverged, 2 threw on both sides**, logs byte-identical
apart from the release id. **That FLAT result is sound and it was called flat in advance on a derived
reason** — Rapid Spin appears 0 times on the frozen pool's sheets. The lab-versus-pool split worked
exactly as ruled on 2026-08-23.

**What does not hold up is the explanation for the sample size.** The account attributes 777 (against
the published run's larger sample, same declared pins) to the frozen pool's cache rebuilding.
Reading `engine/diff_swarm.js#loadTeams`:

- the cache key is the **size and mtime of the store it was handed** (`poolKey(storeDir)`);
- a MISS prints a loud line and **rebuilds from that same store**, deterministically;
- so a rebuild changes the ~41 seconds it costs, **not the teams it yields**.

Measured on this pass, `data/diff-team-pool.json` currently holds **13,571 teams** under the key
`games.bo3.jsonl:227347410:…`, which is the **LIVE** store — `data/team-pool-frozen/games.bo3.jsonl`
is 109,006,606 bytes. So the next pinned run will miss and rebuild, correctly, from the frozen store.

**Conclusion: the pair is valid against itself and the difference against the published run is
unexplained.** It is recorded as open rather than closed with a plausible sentence. A sample that
changes size under fixed pins is the "not the same question" failure CLAUDE.md records, and it should
be settled **before** the next `--write`, because the next `--write` is what republishes the gating
figure.
