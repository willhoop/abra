## 2. FIX ONE — Imprison set a volatile and sealed nothing

**Authority.** `data/moves.ts:9492-9524`. Champions carries no `imprison` row
(`data/mods/champions/moves.ts` is grepped by the probe on every run, not trusted from prose).
The condition is two handlers:

```
onFoeDisableMove(pokemon)              <- the MENU half
onFoeBeforeMovePriority: 4,
onFoeBeforeMove(attacker, defender, move) {
  if (move.id !== 'struggle' && this.effectState.source.hasMove(move.id) && !move.isZOrMaxPowered) {
    this.add('cant', attacker, 'move: Imprison', move);
    return false;
  }
}
```

**What was wrong.** `data/abra-tags.js` has carried the whole rule for as long as the tag has
existed — `sealsMoves {turns:null, scope:'both foes', fromUsersOwnMoves:true}` — and **nothing in
`engine/medicham2-browser.js` read `fromUsersOwnMoves`.** The volatile landed and agreed leaf for
leaf with the authority, so the mechanic read healthy from every direction except the one that
matters: a foe could click a move the Imprison user carries, it dealt its damage, and it spent its
PP — which the authority does not, `deductPP` sitting below the BeforeMove event
(`sim/battle-actions.ts:280-284`).

**Live, named, before the edit.** Game `...-2662961896 vs ...-2663516978`, board-material row 13 —
authority `|cant|p1b: Floette|move: Imprison|Dazzling Gleam`, this engine
`|move|p1b: Floette|dazzlinggleam|p2a: Overqwil`, and the boards then part on eight leaves including
a Farigiraf that faints on one engine and not the other.

**Probe** — `tests/probe_imprison_seal.js`, four staged boards against the authority.

| arm | red-first (clean engine, before) | after |
|---|---|---|
| `imprison-refuses-a-move-the-user-knows` | **DIFFERS** — `p1.active[0].hp ours 78 / authority 130`, `p2.pp[0].shadowball ours 1 / authority 0` | IDENTICAL |
| `imprison-does-not-touch-a-move-the-user-lacks` (Ice Beam; the imprisoner does not carry it) | IDENTICAL | IDENTICAL |
| `imprison-does-not-seal-the-users-own-side` (the imprisoner's ALLY clicks the same move) | IDENTICAL | IDENTICAL |
| `no-imprison-and-the-same-click-lands` (vacuity guard) | IDENTICAL | IDENTICAL |

Counters are read as a **delta around each arm** (the harness is cached, so a total would let arm 1's
refusal vouch for arm 3's silence): `imprisonRefusedAtExecution` +1 on the live arm and +0 on all
three controls. `MEDI_IMPRISON_SEALS_NOTHING=1` restores the pre-fix engine — under it the live arm
is DIFFERS, the three controls stay IDENTICAL, the counter reads 0, and
`MEDFAILS.imprisonSealsNothingRestored` is asserted **present on the knob and absent clean**, so a
dead knob cannot read as a pass.

**Membership printed before wiring**, over the whole move table: `sealsMoves.fromUsersOwnMoves ===
true` matches **exactly one** move (`imprison`), and the six members that do not — encore, disable,
gravity, taunt, throatchop, torment — are printed beside it on every run. The sealed volatile's name
comes from that same move's `statusInflict` (`to: 'user'`), so nothing is named in the engine.

**The fixture had to be a MID-TURN Imprison and that is not a convenience.** On the turn *after*,
Showdown's own request marks the move disabled and refuses the choice outright, so the only case a
script can express is the one where both bodies chose while the move was still legal and the faster
Imprison resolved first. That is also the shape of the live row.

**One probe bug found and fixed before it could lie.** The first draft created a bare `global.window`
to catch `data/abra-tags.js`'s assignment. That is not inert: `data/move-effects.js` writes to
`window.MOVE_EFFECTS` **when a window exists** and to `globalThis` otherwise, while medicham2's
`moveFxTable()` reads back off `globalThis` — so inventing a window made the engine throw
`MOVE_EFFECTS not loaded` mid-game and the arm reported **THREW**, which reads exactly like a broken
engine. The tags are now read in a `vm` sandbox.

## 3. FIX TWO — the pivot road never asked `bounceOff`

**Authority.** `magicbounce.onTryHit` (`data/abilities.ts`) does not re-aim, it **hands the move
over**: it builds a fresh active move and calls `this.actions.useMove(newMove, target, {target:
source})`. For a `selfSwitch` move that decides which body leaves the field, because
`source.switchFlag = move.id` is written against that source (`sim/battle-actions.ts:1311`).

Measured on the authority alone, one staged turn, Incineroar Parting Shot into a Magic Bounce Espeon:

```
|move|p1a: Incineroar|Parting Shot|p2a: Espeon
|move|p2a: Espeon|Parting Shot|p1a: Incineroar|[from] ability: Magic Bounce
|-unboost|p1a: Incineroar|atk|1
|-unboost|p1a: Incineroar|spa|1
forceSwitch [true,false] on P2      <- ESPEON leaves. Incineroar does not.
```

**What was wrong.** `bounceOff` has existed since WIRE 33 and is called at six sites. The
`kind === 'switch'` branch — the only road Parting Shot takes — was not one of them; it resolved its
target with a bare `reaimToSlot`. So the drop landed on the **bouncer** and the **clicker** pivoted:
both halves backwards.

**Live, named, before the edit.** Game `...-2655360057`, board-material row 18 — authority
`|move|p2a: Clefable|Parting Shot|p1a: Grimmsnarl|[from] ability: Magic Bounce`, this engine
`|-unboost|p2a: Clefable|atk|1`, and the boards then part on eight leaves including **which body is
standing in p1a for the rest of the game**, both screens and the Tailwind clock.

**Probe** — `tests/probe_pivot_magic_bounce.js`.

| arm | red-first | after |
|---|---|---|
| `magic-bounce-returns-parting-shot` | **DIFFERS** on 14 leaves — `p1.party.incineroar.boosts.atk ours 0 / authority -1`, `p1.active[0].species ours "milotic" / authority "incineroar"`, `p2.party.espeon.boosts.atk ours -1 / authority 0` | IDENTICAL |
| `synchronize-espeon-takes-the-drop` — **the knob-cleared control**, same board, Espeon's OTHER legal ability | IDENTICAL | IDENTICAL |
| `uturn-is-not-reflectable` — a pivot with no `reflectable` flag, same ability | IDENTICAL | IDENTICAL |
| `taunt-still-bounces` — a reflectable move that is NOT a pivot, same ability | IDENTICAL | IDENTICAL |

Two counters, deliberately apart, because the second is the half a half-fix would be missing:
`bounceAnnounced` (a bounce happened) and `pivotBouncedToTheBouncer` (the switch changed hands).
Live arm +1/+1; Synchronize +0/+0; U-turn +0/+0; **Taunt +1/+0** — it bounced, as it always did, and
acquired no pivot. `MEDI_PIVOT_IGNORES_BOUNCE=1` reds the live arm alone and leaves Taunt green,
which is what says this was one shut door on one branch rather than a broken ability.

**Membership printed before wiring**, re-derived every run: 60 reflectable moves, 7 pivots, and the
intersection this widens is **exactly one — `partingshot`**. `batonpass`, `chillyreception`,
`flipturn`, `shedtail`, `uturn` and `voltswitch` carry no `reflectable` flag and go straight through.

**Espeon clicks Calm Mind and not Protect, and that is measured rather than tidy.** The `protect`
condition carries `onTryHitPriority: 3` and Magic Bounce's `onTryHit` carries none, so a Protecting
bouncer would refuse the move ABOVE the ability and every arm would be vacuously green.

**What moved in the engine besides the target.** After a bounce the SOURCE is the bouncer, so the
four readers that ask "who threw this" — the try-hit refusal, the move-class block, the per-stat drop
refusal and Defiant's retaliation — were repointed at `_bi.bouncedBy || m`. Without that a bounced
Parting Shot reads as **self-inflicted** (`_pt === m`) and Defiant never fires. The switch itself
flips every array with it (`switchOut` reads the outgoing body's own side and the opposing actives),
and `a.to` is deliberately **not** carried across: it names a replacement the caller picked for the
clicker's side, and the body leaving is now on the other one.

`tests/probe_partingshot_mirrorarmor.js`, `tests/probe_partingshot_conditional.js` and
`tests/probe_defog_target_side.js` — the three other probes over this branch — were re-run and are
green.

## 4. THE VOID MISS, ATTRIBUTED

VOID was called at 6 and measured 4. The mechanism is in the artifact, not in a guess:

```
unshared_address_shapes             acc partingshot [sd only]:  8  ->  5
mid_void.low_identity_by_category   {crit 6, dmg 6, acc 5, sec 4}  ->  {crit 4, dmg 4, acc 3, sec 3}
```

The authority took an accuracy draw for the **bounced** Parting Shot use that this engine never took,
because this engine did not bounce. Three of those eight unshared draws are now shared, and two games
crossed back over the 0.9 overlap floor. **A VOID game is the instrument's streams parting, not the
engine's** — so this is a fix reaching the instrument's own identity check, and it should have been
predicted. It was not.

## OWED

1. **`vol.charging` — the defect is confirmed and the PROBE CANNOT BE WRITTEN, and the blocker is the
   instrument, not the mechanic.** `scripted()` in `engine/game_differential.js` reads
   `const tt = (act.moves[k] && 'target' in act.moves[k]) ? act.moves[k].target : dm.target;`, and
   Showdown's request for a **locked** move (`Pokemon#getMoves(lockedMove)`, `sim/pokemon.ts`) carries
   no `target` field at all — so the encoder falls back to the dex row, supplies a target, and
   `Side#chooseMove` (`sim/side.ts:669`) refuses the whole choice: *"Can't move: You can't choose a
   target for Solar Beam."* All ten charge moves in this regulation are `normal` or `any` targeted, so
   **no staged scenario in this repository has ever played a two-turn release turn.** The UNSCRIPTED
   chooser in the same file already has the correct rule — `const tt = ('target' in mv) ? mv.target :
   null;` — with a comment recording this exact bug and its four thrown games; only `scripted()` was
   never updated. It is a one-line change to a file this batch does not own, which is a frozen release
   SOURCE and whose `directed` block the change can move, so it was **reported, not made**.
2. **The MENU half of Imprison (`onFoeDisableMove`) is not wired, and it is declared in the engine
   rather than hidden.** `moveDisabledBy(me, id)` takes one body; whether a move is imprisoned is a
   fact about the FOES, so wiring it is a signature change across `selectableMoves`, `mustStruggle`,
   `struggleSource`, `illegalMoveNow` and the priors sampler. It is invisible to the whole-game
   differential (every click there comes from Showdown's request), so its cost is confined to a
   rollout choosing a move it will then be refused — which is what the authority does anyway when the
   Imprison lands mid-turn. No counter was added for it, because a counter for something that cannot
   fire reads like one that is broken.
3. **Imprison's Struggle exemption is asserted by SOURCE READ, not by a game.** The script language
   has no word for Struggle and the request only offers it once every slot is empty. Stated as such in
   the probe; the check is bounded to the function body, after a first draft that fell back to the
   whole file and passed vacuously on any engine containing the word.
4. **Three named rows of the 35 are diagnosed and unfixed.** Roseli Berry not eaten under a SPREAD
   super-effective hit (`...-2659988022`: the authority ate it under the effectiveness line and this
   engine went straight to `-damage`); `p2.tailwind 2 <> 3` on a game whose protocol **never parted**
   (`...-2634155984`); and a `-boost atk 1` where this engine writes `-unboost atk 1` on a
   **Staraptor-Mega, whose ability in this regulation is CONTRARY** (`...-2634698673`) — the six lines
   of card context do not reach the action that caused it, so nothing is claimed here beyond the
   ability name, which is derived from the format.

   been run**, so the `<!-- GENERATED -->` block at the top of that file is one restamp behind the
