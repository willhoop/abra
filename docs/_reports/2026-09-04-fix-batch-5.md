## 2. FIX 1 — A PARTIAL TRAP CHIPS ONE TURN LONGER THAN THE AUTHORITY

**Probe:** `tests/probe_trap_duration.js`. **Knob:** `MEDI_TRAP_TICK_BEFORE_CLOCK=1`.

**Authority.** `data/conditions.ts:222-252` (`partiallytrapped`, `duration: 5`, `durationCallback`
returning `this.random(5,7)`, `onResidualOrder: 13`), driven by `sim/battle.ts:515-523` inside
`fieldEvent('Residual')`:

```
if (eventid === 'Residual' && handler.end && handler.state?.duration) {
  handler.state.duration--;
  if (!handler.state.duration) { handler.end.call(...); continue; }   // SKIPS onResidual
}
```

The decrement is ABOVE the handler and the expiring residual does not chip. `duration: 5` is four
chips. `data/tags.json` had been recording that all along as this family's `partialTrap.turns`
("4-5"), on **7 of 7** members, beside the `duration` (5) the engine read.

medicham2 chipped, then decremented, then ended — so it ended on the authority's residual and took
one extra chip getting there. Champions overrides neither (`data/mods/champions/conditions.ts` holds
par/slp/frz only).

**RED FIRST**, against the official simulator on a derived fixture (Araquanid's Infestation into a
Snorlax; both engines read on their own hp and their own trap state):

```
medi  maxhp 235  per-turn loss [36,29,29,29,29,0,0,0]  trap gone after turn 5
sd    maxhp 235  per-turn loss [41,29,29,29, 0,0,0,0]  trap gone after turn 5
FAIL  TEST — the residual chips after the landing turn agree with the authority
        medi 4 chip(s), authority 3 chip(s)
FAIL  COUNTER — partialTrapTick=ABSENT  partialTrapExpired=ABSENT
```

**AFTER:** `medi 3 chip(s), authority 3 chip(s)`, trap gone after turn 5 in both,
`partialTrapTick=4 partialTrapExpired=1`, and the knob child exits 1. The three controls — a
non-trapping click of the SAME attacker chips nothing in either engine; the chip AMOUNT is one value
and agrees; the LANDING turn still carries a chip on top of the hit — were green before AND after, so
the fix is a clock and not arithmetic, and it did not buy the test arm by deleting the landing chip.

## 3. FIX 2 — HEAL BLOCK RUNS A TURN LONG AND LAPSES SILENTLY

**Probe:** `tests/probe_healblock_clock.js`. **Knob:** `MEDI_HEALBLOCK_CLOCK_LONG=1`.

**Authority.** `data/moves.ts:8276-8345`, `healblock.condition`: `duration: 5`, with
`durationCallback` returning **2** for Psychic Noise, `onResidualOrder: 20`, and
`onEnd(pokemon) { this.add('-end', pokemon, 'move: Heal Block'); }`. Same `fieldEvent` clock as
above. Champions overrides neither `healblock` nor `psychicnoise`.

Psychic Noise (349 uses) is the format's ONLY `blocksHealing` carrier, so this is the whole mechanic.

medicham2 set `_healBlock = turns + 1`, and its lapse branch wrote no line at all — the file's own
comment said so: *"It announces nothing when it lapses in this engine."*

**RED FIRST** (Chimecho's Psychic Noise into an Aurorus holding Leftovers):

```
medi  hp by turn [71,71,71,83,95,107]     healed on [4,5,6]    `-end` on []
sd    hp by turn [93,93,105,117,129,141]  healed on [3,4,5,6]  `-end` on [2]
FAIL  the number of residuals that REFUSE the heal    medi 2, authority 1
FAIL  healing resumes on the same turn                medi 4, authority 3
FAIL  medicham2 announces `-end … Heal Block`         medi [], authority [2]
FAIL  COUNTER  healBlockApplied=1 healBlockExpired=ABSENT
```

**AFTER:** refused 1 / 1, healing resumes on turn 3 in both, `-end` on turn 2 in both,
`healBlockApplied=1 healBlockExpired=1`, knob child exits 1. Controls green on both arms: the same
attacker's non-blocking click heals on every later turn in both engines, and the per-turn heal amount
is one value and agrees. **The announcement was also added to the `MEDI_ENDTURN_CLOCKS_AT_FOOT=1`
path**, deliberately, so that knob stays a POSITION control — the probe passes under it too, verified.

The board half of the corpus game is the clock, not the line: the authority's block had lapsed, so
the Sitrus fired; ours was still running, so the berry stayed in the pocket and Garchomp stayed 45 hp
down.

## 4. FIX 3 — PERISH SONG: THE REFUSAL AND THE EMPTY CLICK

**Probe:** `tests/probe_perishsong_field.js`. **Knob:** `MEDI_PERISH_ALWAYS_ACTIVATES=1`.

**Authority.** `data/moves.ts`, `perishsong.onHitField`, read whole:

```
let result = false;  let message = false;
for (const pokemon of this.getAllActive()) {
  if (this.runEvent('Invulnerability', pokemon, source, move) === false) { add('-miss', ...); result = true; }
  else if (this.runEvent('TryHit', pokemon, source, move) === null) { result = true; }
  else if (!pokemon.volatiles['perishsong']) { addVolatile; add('-start', ..., '[silent]'); result = true; message = true; }
}
if (!result) return false;
if (message) this.add('-fieldactivate', 'move: Perish Song');
```

Two facts the engine did not carry. **A body that already holds the clock raises neither flag**, so a
second Perish Song into a counting field affects nobody, `result` stays false, and the MOVE FAILS
(`|-fail|<the singer>`) — seven of the 141 protocol divergences, across five configurations. And the
`TryHit === null` arm is where `soundproof.onTryHit` answers (`if (target !== source &&
move.flags['sound'])`, and Perish Song carries `flags: { sound: 1 }`); medicham2's perish branch
asked `tryHitRefusal` (`refusesStatusMoves`, Prankster, the type absorbers) and never asked
`moveClassBlocked`, the reader **fifteen other branches in the same file already call beside it**.
Champions overrides neither handler; the only `perishsong` hits under `data/mods/champions/` are in
`learnsets.ts`.

**RED FIRST** (Absol's Perish Song into an Abomasnow, whose two legal abilities are the knob):

```
medi  clocks [3,3,3,3]     activate 1  fail 0  immune []
sd    clocks [3,3,null,3]  activate 1  fail 0  immune ["|-immune|p2a: Abomasnow|[from] ability: Soundproof"]
FAIL  a soundproof body takes NO perish clock       medi 3, authority null
FAIL  both engines announce the refusal             medi [], authority [the line above]
FAIL  the SECOND click FAILS and announces nothing  medi fail 0 activate 1 / authority fail 1 activate 0
FAIL  COUNTER  perishMarked=ABSENT perishNoTarget=ABSENT perishClassRefused=ABSENT
```

**AFTER:** clocks `[3,3,null,3]` in both, the `-immune` line naming Soundproof in both, the second
click `fail 1 activate 0` in both, `perishMarked=11 perishNoTarget=1 perishClassRefused=1`, knob
child exits 1. Controls green on both arms: the SAME Abomasnow carrying Snow Warning instead TAKES
the clock in both engines (so the refusal is the ability, not the fixture); the other three bodies
are still marked (so it is one body, not the move); the first click still activates and fails in
neither; and nobody's clock is RESET by the second click — the counters read `[2,2,2,2]` in both.

**DECLARED REMAINDER, WRITTEN INTO THE ENGINE AT THE BRANCH:** the authority's Invulnerability arm
writes `add('-miss', source, pokemon)` and this engine still writes nothing. The flag is raised so
the move cannot spuriously fail; the LINE is owed and unprobed.
