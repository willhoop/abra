## 6. THE UNEXPLAINED 777-GAME SAMPLE: IT WAS `--games 960`

5.265.0 recorded, correctly, that a matched pinned pair read 777 games where the published run read
961 under the same declared pins, and left the cause OPEN rather than guessing. **The cause is
`--games`, reproduced deterministically against the frozen store** — the sweep is MEASURE's earlier
run today and is recorded in `docs/_reports/2026-09-06-pool-pin-and-remeasure.md`, which carries the
full five-row table; the two rows that settle it are:

| `--games` | picked | pool digest | games in the primary arm |
|---:|---:|---|---:|
| 960 | 1,597 | `b2b61ec40281` | **777** |
| 1200 | 1,968 | `0d103fb9fa87` | **961** |

The rapidspin pair was run at `--games 960`; the published run at `--games 1200`. The pool cache is
not implicated, and the earlier reading of `loadTeams` — key on size and mtime, a miss rebuilds
deterministically, so a rebuild moves elapsed time and not teams — was right. It simply did not have
the missing variable.

**THE LESSON, AND IT IS THE DURABLE HALF OF THIS PASS. `--games` IS PART OF THE SAMPLE DEFINITION,
NOT A BUDGET.** Two runs on identical declared pins and different `--games` draw different strides
and are not a before/after. `arms_comparable.js` already refuses on `games` differing, so the guard
exists — but **a report that records the pins and not the command cannot be audited**, and that is
exactly what happened. Record the whole command, every time.

  `2fd61bf80133` while `source_digests` carries `data/games.bo3.jsonl` `da8597c45bb8`, the live one.
  **A receipt that describes the wrong store is worse than no receipt.**
- **#548** — `engine/game_differential.js` throws for any `--turns` below 3.
  `identicalAtEndOfTurn` is `[1, 2, 3].map(earlyRate)` at `:7837`; `agreementByTurn` runs

  at `:7865-7867` indexes `agreementByTurn[i]` for `i` in 0..2, so at `--turns 2` it reads
