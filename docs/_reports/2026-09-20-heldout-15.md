## 3. THE PROTECT CLASS — 4 of 15, FIXED

### The authority, read this run

Both handlers are gathered into the same `TryHit` event and `Battle#runEvent` sorts them by
`compareLeftToRightOrder` (`sim/battle.ts:421-426`), **priority first**:

| handler | priority | source |
|---|---|---|
| `protect.condition.onTryHit` → `this.add('-activate', target, 'move: Protect'); return this.NOT_FAIL;` | **3** | `data/moves.ts:13986` |
| `magicbounce.onTryHit` → `this.actions.useMove(newMove, target, {target: source}); return null;` | **1** | `data/abilities.ts:2428` |

3 > 1, and Protect's `NOT_FAIL` ends the event, so **a bouncer behind its own shield blocks and does
not reflect**. Neither key is overridden in `data/mods/champions/`; the probe greps both on every run
and refuses to assert anything if the priorities ever stop ordering that way.

### What was wrong

`engine/medicham2-browser.js` already held this rule **at one of its two bounce sites**.
`bounceAtTryHit` — added 2026-09-19 for the five dispatch kinds — opens with
`if(shieldRefuses(t,mv))return {src:m,t,bounced:false};`, and its header carries the priority reading
above. `statusMoveTargets`, where Screech, Soak, Taunt, Parting Shot and every other generic
reflectable status click resolves, called `bounceOff` **bare**, and the shield was asked afterwards at
STEP 1 of the gauntlet — by which point the target had already been rewritten to the bounce
destination. One fact, two implementations, one of them missing half of itself.

### Row 2 (`…2654574813`, omit-weather, turn 9) — CANNOT be a die

`spicyspray.onDamagingHit` (`data/abilities.ts:4456-4467`; `data/mods/champions/abilities.ts:85` is

```js

```

**There is no `randomChance`.** The burn attempt is unconditional. So the authority's silence is not a
lost roll — something refused the status **silently**, and this engine modelled no refusal at all.
Derived, not recalled: `scovillainmega` has exactly one ability, `Spicy Spray`; `sinistcha` is

**The lead, stated as a lead:** Showdown has silent `onSetStatus` refusals that write no line when the
source effect is an ABILITY rather than a Move — `safeguard.onSetStatus` returns `null` and only calls
`this.add('-activate', …)` for `Synchronize` or a secondary-less MOVE. A side condition or terrain
standing outside the 16-line dump window would produce exactly the observed asymmetry. **Not
confirmed. I could not stage it:** `buildPair` will not write `Spicy Spray` onto base Scovillain (both
engines then ignore it, measured), and staging the mega inside a scripted game was out of budget.
