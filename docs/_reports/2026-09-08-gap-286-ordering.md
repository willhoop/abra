## 2. WHICH ENGINE IS WRONG, AND ABOUT WHAT — READ OFF EACH SIDE, NEITHER ASSUMED

A parted order has exactly two causes and they need different fixes: the engines disagree about the
SPEED they sorted on, or they agree about the speed and disagree about WHEN they sorted. The probe
now asks the first question, so the second is not an inference. `speedRows` is the differential's own
boundary-by-boundary comparison — the authority's `pokemon.getActionSpeed()` against this engine's
`effSpeed()`, for every active body at every boundary, carrying ONLY the readings that DISAGREE.

```
REAL arm, fixed engine   : speed readings that DISAGREE = 0   [desyncs 0]
REAL arm, under the knob : speedDis = 0, and the order STILL parts
```

**Both engines put the same number in the sort key, under both placements.** So the defect is not the
speed and cannot be: it is *when the queue was sorted*. **medicham2 was wrong; the authority was
right.** New assertion in the probe, and a new control assertion that the knob moves the ORDER without
moving the NUMBER — if it had moved a speed reading, the diagnosis would have been the other one.

### The authority's rule, cited

`Battle#runAction`, `pokemon-showdown/sim/battle.ts`:

| line | statement |
|---|---|
| 2856-2858 | `if (this.gen >= 5 && action.choice !== 'start') { this.eachEvent('Update'); ...` |
| 2915-2922 | `if (this.gen >= 8 && (this.queue.peek()?.choice === 'move' \|\| ...)) { this.updateSpeed(); for (...) this.getActionSpeed(queueAction); this.queue.sort(); }` — the **last** statement of `runAction` |

Priority itself is computed in `Battle#getActionSpeed`, `sim/battle.ts:2637-2645` — the base move's
printed priority, then `singleEvent('ModifyPriority')` and `runEvent('ModifyPriority')`, then
`action.priority = priority + action.fractionalPriority`. Speed is `action.pokemon.getActionSpeed()`
at `:2657`.

So the Update pass that spends an `onUpdate` item is **above** the re-sort. medicham2 has no queue
object — the tail of action k-1 is emulated at the top of iteration k — and it called `_resortTail`
ABOVE `_updateAll()`, i.e. above the pass carrying `restoreStatsAll`, which is White Herb's only
mid-turn door in this engine. The doubling therefore arrived one whole action after the sort that
needed it.
