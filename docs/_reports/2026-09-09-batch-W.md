## 2. PRIORITY 2, DEFECT A — **THE BOUNCED SLEEP POWDER: THE ADDRESS, NOT THE DRAW**

### The prediction that was wrong, and the measurement that corrected it

Batch V filed this as *"needs an accuracy draw, which moves the die stream and can void games"*. **It
needs no new draw at all.** Read off the authority rather than off the card:

- Magic Bounce is `onTryHit` with `onTryHitPriority: 1`, and `hitStepTryHitEvent` is **step 2 of
  eight** while `hitStepAccuracy` is **step 5**. So the ORIGINAL click never reaches a die when it is
  bounced — the target is filtered out three steps above it.
- `this.actions.useMove(newMove, target, {target: source})` is a WHOLE MOVE with the BOUNCER as its
  source. It runs its own eight steps, so the **copy takes the one accuracy draw of the pair**, and
  `useMoveInner` writes `activeTarget = source` for it.

So the count is **one on both engines**. What differs is the ADDRESS. The middle arm addresses every
draw as `FNV1a(seed | turn | category | activeMove.id | activeTarget.side.id+position | nth)`
(`engine/game_differential.js`, `midDraw`); this engine's `MID_TGT` is written once at the top of the
action from the target the CLICK named (`_midWriteActionAddr`) and nothing moved it when the move
changed hands. **We drew at `…|sleeppowder|p1a…` where the authority drew at `…|sleeppowder|p2a…`.**

Two engines answering different questions with the same number of draws — which is exactly why no
identity or void check ever saw it.

### RED FIRST — `tests/probe_bounce_accuracy_address.js`

Three arms, the card's own bodies, six turns each (a bounced Sleep Powder sleeps the CLICKER for one
or two turns, so the script has to outlast that to get a second bounce).

| arm | clean | under `MEDI_BOUNCE_KEEPS_SOURCE=1` |
|---|---|---|
| **`bounce-sleeppowder`** RED | AGREE 6/6, 3 bounces, `bounceAddressReaimed` **3** | **PARTS** at `showdown |-miss|p1a: Hatterene|p2a: Vivillon` vs `medicham |-status|p2a: Vivillon|slp|…` — **the card, line for line** |
| `bounce-cleared-healer` CONTROL | AGREE, 0 bounces | AGREE |
| `nobounce-at-the-partner` CONTROL | AGREE, 0 bounces | AGREE |

`bounce-cleared-healer` is the knob cleared **explicitly**: same board, same script, one field —
Hatterene's ability is Healer (slot 0) instead of Magic Bounce (slot H) — and the bounce count goes
3 → 0. `nobounce-at-the-partner` is the over-fire control that matters: the Magic Bounce Hatterene is
**still on the field** and the identical Sleep Powder is aimed at the non-bouncing Slowbro beside it,
so a change that re-addressed EVERY status move's die would part here.

**AND THE RED ARM CARRIES A SECOND BAR**, because "the engines agree" is also what an engine that made
every bounced move miss would produce: the agreed stream must hold **at least one LANDED bounce and at
least one MISSED one**. It reads **2 landed, 1 missed**.

### The fix

`engine/medicham2-browser.js`, the `kind === 'status'` branch. Three things move and they are ONE
fact — *a bounced move is the bouncer's move* — so they are one knob:

- the DRAW's address: `MID_TGT = midEventSlot(t)`;
- the ACCURACY's owner: `hitChance(_bSrc, t, …)`, because the modifiers are read off `newMove`'s
  source;
- the `-miss` LINE: `TR.miss(_bSrc, t)`, because `hitStepAccuracy` writes `add('-miss', pokemon,
  target)` with `pokemon` being the source. **Without this third part the address fix would have
  REPLACED one divergence with another** — `|-miss|p2a|p2a` against `|-miss|p1a|p2a` — which is why it
  is not a separate batch.

`_bSrc` is `m` on every road with no bounce in it, so the call is character-for-character the old one
everywhere else. New counter `MEDSEEN.bounceAddressReaimed`, a strict subset of
`statusBouncedBackAtUser` that must EQUAL it on any run that bounced anything.

**WHAT IS NOT MOVED, DECLARED RATHER THAN LEFT TO BE FOUND** (both written into the engine comment):
the status is still applied with the CLICKER as its source, so Safeguard and Synchronize still
attribute it wrongly; and `newMove.pranksterBoosted = false` is not modelled, so a Prankster clicker's
bounced move is still refused by a Dark type. Neither is exercised by the card and folding either in
would have made the arm above unattributable. **Both are owed.**

## 3. PRIORITY 2, DEFECT B — **INSTRUCT'S PP CLAUSE, AND A CORRECTION TO BATCH V**

### The engine already knew, and asked one step too late

The card is `|-fail|p2a <> |-singleturn|p1a|instruct`, and **our own next line names the cause**:

```
agreed    |move|p2a: Oranguru|instruct|p1a: Gengar
showdown  |-fail|p2a: Oranguru
medicham2 |-singleturn|p1a: Gengar|move: Instruct|[of] p2a: Oranguru
          |cant|p1a: Gengar|nopp|protect
```

Instruct's `onHit` (mainline — Champions overrides 259 moves and Instruct is not one of them,
re-derived on every probe run) ends its refusal list with `(moveSlot && moveSlot.pp <= 0)`. Gengar's
last move was the Protect it clicked on turn 10 and that slot was empty. The branch here checked the
shield, Good as Gold, the `refuses` list, `_charging`, `_recharge` and `!t._lastMove` — **every clause
except that one** — so it queued the repeat and then refused it one step later, printing two lines the
authority does not carry.

`ppLeft(t, _mid) === 0`, not `!ppLeft(...)`: `ppLeft` answers `null` for a move with no PP row, which
is the same "there is no slot to ask about" as the authority's falsy `moveSlot`, and a null must not
refuse.

### RED FIRST — `tests/probe_instruct_lastmove_pp.js`, shown red on the PRE-fix bytes

The arms **drain a real slot** rather than declaring one empty: Protect is `maxpp` **8** in this format
(derived off the release's `data/tags.json`, printed every run — never the mainline 16), and the target
clicks it on eight consecutive turns. Snorlax is base 30 against Oranguru's 60, so on the Instruct turn
the target has not acted and `lastMove` is still the previous turn's Protect — which is the card's
shape, and the only way to ask the PP clause without a shield standing in front of it.

`instruct-lastmove-at-one-pp` is the knob cleared explicitly — the identical script with **one fewer

*"this body cannot select Protect"* passes the red arm and breaks this one.
