## What was built

### `engine/engine_release.js` — `classifyChange(frozen, live)` and `driftDiagnosis(id, opts)`

`classifyChange` takes two buffers and returns one of five labels, and only these five:

| class | meaning |
|---|---|
| `same` | byte-identical. Not drift. |
| `eol-only` | different bytes, identical once line terminators are normalised. **Nobody edited a character.** |
| `changed` | different content. A re-measurement is owed. |
| `gone` | the live file is not there. Stronger than `changed`, never weaker. |
| `unavailable` | the frozen bytes are not there (a pruned release). **UNANSWERABLE, and answered as such.** |

`driftDiagnosis(id)` walks a release manifest, reads bytes only for the files whose digest actually
moved, classifies each, and returns a verdict plus a one-line summary a refusal can quote verbatim.
Verdict precedence is **content dominates**: a mixture of a real edit and a line-ending change reports
`CONTENT-CHANGED`, never `EOL-ONLY`. `UNDIAGNOSABLE` outranks `EOL-ONLY`, because a pruned release
cannot rule out a content change and the reassuring answer is the dangerous one.

A fifth verdict, `SOURCE-SET-GREW`, covers the third way an id moves that is neither a byte nor a line
ending: `SOURCES` itself grew, which it has done four times, and every growth retroactively gives the
tree a new id with nothing edited.

`opts.against <id>` asks the same question about two snapshots. That is the form the question actually
arrived in on both bad nights — *these two ids differ, why* — and without it the next person writes a
`node -e` that reads two snapshots and compares them, which is the hand-rolled second implementation
this repository has paid for repeatedly.

### `engine/pin_guard.js` — the diagnosis at the point of discovery

`pin_guard.guard()`'s `wrong_release` branch is where the mismatch is actually found. It now appends
`driftDiagnosis(pinnedId).summary` to the refusal's `why` and records `drift_cause` on the result.

**`engine/status.js` and `engine/quarantine.js` need NO EDIT** — and that is the point, not an
omission. `status.js:1209` renders each clause's whole `why` verbatim (deliberately: a 150-char prefix

## What this does NOT do

- **It does not change what the digest computes.** `treeDigest()` still hashes raw bytes. The id still
  moves on a line-ending change. Artifacts pinned to the old id are still stranded. `open()` still
  refuses a modified snapshot. `pin_guard` still WITHHOLDS every figure. It is a diagnosis, not an
  exemption, and the CLI prints that sentence under every verdict.
- **It does not pin the nine.** `.gitattributes:70-77` names `medicham2-browser.js`, `rollout_leaf.js`,
  `position_features.js`, `engine/tags.js`, `mc_key.js`, `set_priors.js`, `smogon_priors.js`,
  `data/quality-filter.json` and `data/engine-data.js` as CRLF in the working tree, and states that
  pinning them to LF would rewrite them, move every release id, and break `tests/roster.js`, whose red
  demonstrations match `\r\n` against the simulator's source. Untouched.
- **It does not normalise the comparator.** The repository's own record: *never normalise the
  comparator to hide it.* Untouched.
- **`eol-only` does not mean "fine".** It means *nobody edited a character*. A line terminator inside a
  template literal is semantic, and `tests/roster.js` matches `\r\n` on purpose. The summary says so in
  those words, and probe checks 1f/1g pin that the wording never offers the pinned artifact back as
  reusable.

### Why a trailing-CR-insensitive comparison is safe as a diagnosis and would not be as the digest

The digest is an **identity**: it decides whether a measurement may be reused, and a wrong answer there
publishes a number about bytes nobody ran. The comparison here **decides nothing** — it changes no id,
un-strands no artifact, permits no re-use, and gates nothing. It only labels a difference the raw-byte
digest has *already* detected. A wrong label costs one misleading sentence; a wrong digest costs a void
measurement. That asymmetry is the entire argument, and it is why the normalisation lives in the
reporter and never in `sha12`.

It also deliberately does **not** go through `engine/read_text.js`, this repository's one implementation
of "read a text file whatever its line endings". That is the right door everywhere else and the wrong
one here: it exists to make the distinction invisible, and the distinction is what is being measured.

### A bug this found in itself

The first terminator counter used `/(?:^|[^\r])\n/g`, which consumes the character before the newline
and therefore counted a blank line once instead of twice. Against the live tree it printed
*"the frozen copy has 39866 LF, the live copy has 39932 CRLF"* for two files that are content-identical
— a difference in the alarming direction, printed by the line built to stop a false alarm. Fixed to a
lookbehind `/(?<!\r)\n/g`; counts now agree at 39932/39932. Probe check 1h pins it, and the fixture
gained a blank line specifically so it can see it.

## The mechanism underneath, for whoever takes the larger job

`git config core.autocrlf` is **`true`** on this machine. `engine/generated_audit.js:68` already records
the shape: *"a file a GENERATOR last wrote carries LF"*, and a git operation that touches it writes CRLF
back. The three files that keep flipping — `medicham2-browser.js`, `data/tags.json`,
`data/abra-tags.js` — are all generated or hand-edited-then-checked-out, and the two that were already
pinned `eol=lf` after 2026-08-28 (`data/tags.json`, `data/abra-tags.js`) no longer flip. That is
consistent with the pin working and with `medicham2-browser.js` being the remaining exposure. This
report does not act on it; the `.gitattributes` block says why it is a separate job.
