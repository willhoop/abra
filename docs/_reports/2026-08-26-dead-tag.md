## 2. THE AUTHORITY

Mainline `data/moves.ts:11920-11945`, `minimize.condition`. **Champions does not override it** —
`grep -n minimize data/mods/champions/moves.ts` returns nothing.

```js
onSourceModifyDamage(damage, source, target, move) { if (move.flags['minimize']) { return this.chainModify(2); } }
onAccuracy(accuracy, target, source, move)         { if (move.flags['minimize']) { return true; } }
```

The flag is on the ATTACKING move; the handlers live on the TARGET's volatile.

- `onAccuracy` is the **`Accuracy` event**, the last step of `hitStepAccuracy`
  (`sim/battle-actions.ts:729-735`): the stages are computed and then the assignment throws the result
  away, so Minimize's own +2 evasion cannot claw any of it back.
- `onSourceModifyDamage` is the **ModifyDamage relay** (`sim/battle-actions.ts:1826`) — the same chain
  as Life Orb, the resist berries and Friend Guard, so it truncates once with them.

**MEASURED ON THE OFFICIAL SIMULATOR BEFORE ANY ENGINE LINE WAS WRITTEN**, not read and trusted. The
volatile is applied directly so the evasion stage is out of frame and the doubling is isolated:

```
moveHit, roll pinned, Snorlax into Sandaconda      plain -> minimized
  Body Slam                                          52  ->  104
  Heavy Slam                                         49  ->   98
  Ice Beam   (unflagged control)                     78  ->   78

hitStepAccuracy at +6 evasion with every roll FORCED TO FAIL
  Body Slam  volatile absent false   volatile present true
  Ice Beam   volatile absent false   volatile present false     <- the cleared control
```

## 3. THE PROBE, RED FIRST

Prototyped on the same staging the census probe uses (`hitOnRoll`, the accuracy family's helper,
which spends two real turns through `battleTurn`). Before the fix:

```
ACC roll .85  icebeam  protect 508   minimize   0     <- +2 evasion is real
ACC roll .85  bodyslam protect  16   minimize   0     <- SHOULD NOT MISS
DMG roll .50  bodyslam protect  15   minimize  15     <- SHOULD BE 30
DMG roll .50  icebeam  protect 480   minimize 480     <- control, correctly unmoved
```

After:

```
ACC roll .85  bodyslam protect  16   minimize  32
DMG roll .50  bodyslam protect  15   minimize  30
DMG roll .50  icebeam  protect 480   minimize 480
```

and under `MEDI_PUNISH_MINIMIZE_BLIND=1` every number returns to the pre-fix column exactly.

The census row now reads:

> at roll 0.85 into a MINIMIZED Garchomp — Ice Beam 0 (missed, +2 evasion), Body Slam 48 (landed
> anyway); at roll 0.50 Body Slam 23 after Protect vs 46 after Minimize (x2), Ice Beam 244 vs 244
> (unflagged, so unmoved)

**The two moves are never differenced against each other.** The never-miss arm holds the PRINTED
ACCURACY equal (both 100) and the doubling arm compares each move against ITSELF across the
Minimize/Protect knob — the trap the `weightBased` and `needsUntrackedState` corrections were both
caught in.

## 4. THE PATH IS REACHED, NOT MERELY PRESENT

Two counters, kept apart on purpose because `halves` exists to make a one-sided implementation
visible: `MEDSEEN.punishMinimizeNeverMiss` and `MEDSEEN.punishMinimizeDamage`. Both read **4** on the
probe run and **0** under the knob. A run where the first is non-zero and the second is zero means the
doubling has come unwired, and the counter says so instead of the mechanic simply not happening.
