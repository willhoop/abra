measured game and `pr.aN`/`pr.bN` only for the control; a caller that copies the wrong pair gets a
plausible, well-formed, completely different game.

## #5 — a certain PRIMARY volatile throws a die the authority does not (CLOSED)

Dump cause: `event missing from medicham2 :: |-status|p1a|brn|[from]flamebody <> |-weather|sunnyday|[upkeep]`.

Toxapex clicks Infestation into a Volcarona with Flame Body. Showdown burns the Toxapex; medicham2
does not. The address log, both engines, turn 5:

```
  SD 20260813|5|any|infestation|p20|0
  ME 20260813|5|any|infestation|p20|0
  ME 20260813|5|any|infestation|p20|1        <- ME only
```

The extra draw is `engine/medicham2-browser.js`'s `statusInflict` block:

```js
if(rng()*100>=(_e.chance==null?100:+_e.chance))continue;
```

For `partiallytrapped` the chance is 100, so the roll **can never fail** (`rng() < 1`) — it was a
no-op on the board and a real draw on the shared `any|<move>|<slot>` address. Flame Body's own
`randomChance(3, 10)` then read `nth 1` here and `nth 0` there.

The authority has no die at all:

```
sim/battle-actions.ts:1236-1237
  if (moveData.volatileStatus) {
    hitResult = target.addVolatile(moveData.volatileStatus, source, move);
```

`grep volatileStatus data/mods/champions/scripts.ts` is empty, so this is the Champions rule too.

**Population printed before the wire**, over all 500 moves in `data/tags.json`: 52 target volatiles
reach this door, **32 at chance 100** (infestation, firespin, sandtomb, whirlpool, snaptrap, bind,
wrap, encore, taunt, yawn, disable, leechseed, saltcure, smackdown, helpinghand, curse, …). The 20
sub-100 entries are all dex SECONDARIES (Rock Slide's flinch, Hurricane's confusion) and are dropped
by the `_secVol` guard above the roll before they ever reach it — so the fix touches exactly the
certain ones.

Knob `MEDI_PRIMARY_VOLATILE_DIE_ALWAYS=1`, stamp `MEDFAILS.primaryVolatileDieAlwaysRestored`, counter
`MEDSEEN.primaryVolatileDieSkippedCertain`.

## #3 — Mold Breaker does not delete a BREAKABLE evasion ability (CLOSED)

Dump cause: `unrelated event mismatch :: |-damage|p1b|H/H <> |-miss|p2b|p1b`.

A Mold Breaker Tinkaton's Knock Off into a Sand Veil Garchomp standing in its own Sandstorm. Both
engines drew `acc|knockoff` at the *same* address — so it is not a die defect — and the authority hit
for 99 while this engine printed `|-miss|`. `p1.party.garchomp.hp medi 116 / sd 84`.

`hitChance`'s ModifyAccuracy walk read the defender's ability RAW:

```js
for(const [who,mon] of [['att',att],['def',def]]){
  for(const kind of ['ability','item']){
    const r=accModRow(kind,kind==='ability'?mon.ability:mon.item);
```

The authority's guard is inside `runEvent` itself, so it governs **every** event:

```
sim/battle.ts:835-840
  if (effect.effectType === 'Ability' && effect.flags['breakable'] &&
      this.suppressingAbility(effectHolder as Pokemon)) {
    if (effect.flags['breakable']) {
      this.debug(eventid + ' handler suppressed by Mold Breaker');
      continue;
```

and `ModifyAccuracy` is in the `AttackingEvents` list at `:852` as well. Sand Veil is
`flags: { breakable: 1 }` (`data/abilities.ts:4008`); `data/mods/champions/abilities.ts` overrides
neither it nor `moldbreaker`.

**Population printed before the wire**, over the whole ability table: six carriers of
`accuracyMod`/`writesAccuracy`, and exactly three are breakable — **snowcloak 1,218 sheets, sandveil
697, tangledfeet 12**. All three are `side: 'def'`, so the attacker half of the walk cannot move, and
the ITEM half must not (Bright Powder is an item; Mold Breaker does not touch items).

Asked through `suppressedAbility(att, def, _cat)` — the reader `bounceOff`, `absorbedBy` and
`statusRefuser` already use — so the `att === def` exemption, Ability Shield and the `onlyCategory`
gate are not re-derived here.

Knob `MEDI_ACC_ABILITY_UNBREAKABLE=1`, stamp `MEDFAILS.accAbilityUnbreakableRestored`, counter
`MEDSEEN.accAbilityBrokenByMoldBreaker`.

**A residual, named and not fixed:** the same game shows `tgt|knockoff|p21|0` drawn by the authority
and not by this engine, at turns 3 **and** 5. It is a different category bucket, it did not part a
board, and it is left open rather than folded in.

## #1 — a shielded Magic Bounce body reflected a PIVOT (CLOSED)

Dump cause: `unrelated event mismatch :: |-activate|p1a|protect <> |move|p1a|partingshot`.

Incineroar's Parting Shot at a Protecting Magic Bounce Hatterene. The authority wrote
`|-activate|p1a: Hatterene|move: Protect`; this engine reflected the move, dropped Incineroar's stats
and then **pivoted the bouncer out**, bringing a Talonflame in that the authority never moved —
`p1.active[0].species medi talonflame / sd hatterene`.

Both handlers are gathered into one `TryHit` event and sorted by priority: Protect's condition is
`onTryHitPriority: 3` (`data/moves.ts:13986`) against Magic Bounce's `1` (`data/abilities.ts:2428`),
and Protect returns `this.NOT_FAIL`, which ends the event.

**The check already existed and lived at the call sites.** It was added earlier the same day at
`statusMoveTargets` (`bounceRefusedByShield`, `MEDI_BOUNCE_BEFORE_SHIELD`) and `bounceAtTryHit` had
always had it — two of **nine** `bounceOff` call sites. The `pivotStatus` road, whose own header
records that the `reflectable` × pivot intersection in this format is **exactly `partingshot`**,
called `bounceOff` bare. `MEDSEEN.bounceRefusedByShield` read **0** on the replayed game while
`bounceAnnounced` read 1.

Fixed by **hoisting the check into `bounceOff` itself**, beside the Mold Breaker pierce, and reducing
`statusMoveTargets`'s wrapper to the plain call it started as — one fact, one implementation. Same
knob and same counter; no new knob, because it is the same rule.

## #4 — a Substitute-absorbed row still owes a secondary die (DIAGNOSED, NOT FIXED)

Dump cause: `event missing from medicham2 :: |-status|p2b|brn <> |upkeep`.

Sinistcha's Matcha Gotcha (spread, 20% burn) hits a Delphox behind a Substitute and a healthy
Whimsicott. The authority burns the Whimsicott; this engine does not. The address log, turn 11:

```
  SD 20260813|11|sec|matchagotcha|p21|0
  SD 20260813|11|sec|matchagotcha|p21|1      <- SD only
  ME 20260813|11|sec|matchagotcha|p21|0
```

The authority throws **two** secondary dice and this engine throws one, so Whimsicott's roll read
`nth 0` here and `nth 1` there.

The authority's reason, read and not guessed:

```
data/mods/champions/scripts.ts:351-354
  if (damage[i] === this.battle.HIT_SUBSTITUTE) { damage[i] = true; targets[i] = null; }
sim/battle-actions.ts:1338-1343
  for (const target of targets) {
    if (target === false) continue;
    ...
      const secondaryRoll = this.battle.random(100);
```

A doll-absorbed row is set to **`null`, not `false`**, so it survives the `=== false` test and spends
a die. (`runMoveEffects` at `:1191-1196` guards with `if (target)`, which is why the row's *effects*
do nothing there — the comment inside `_stepApply` is right about step 3 and wrong about step 5.)

**Not landed, deliberately.** medicham2's `_stepSubAbsorb` sets `R.out = true` and `_stepApply` returns
at `if(!R.hit&&!R.fainted&&!_secOnly)return;`, which is ABOVE where `_secs`, `dustBlocked` and
`_fmtStripped` are built — so spending the die correctly needs that row construction extracted so one
reading serves both the doll row and the body row, **and** it needs to be spent at the position the
authority spends it (step 5, in target order) rather than at step 0 where `_stepSubAbsorb` runs. Doing
it at `_stepSubAbsorb` would be right for a doll on the FIRST target and wrong for a doll on the
second. That is a refactor inside a hot 400-line block for one game; it is written up here rather than
rushed.

Two further facts for whoever takes it: Shield Dust must **not** filter the doll row's dice (the
authority's `runEvent('ModifySecondaries', null, …)` reaches no target handler), and Sheer Force still
removes them (it nulls `move.secondaries` at ModifyMove, so `secondaries()` returns before the loop).

## An instrument defect found on the way, and it was under-reporting ENGINE's one number

`tests/test-mechanics.js` computes `const works = results.filter(r => r.works)` at what used to be
line 37132 — and **twelve `probe()` calls were registered below it**. `probed: results.length` is read
later, at the write; `live: works.length` is the snapshot. So the artifact published
`probed: 993, live: 984` and the nine-row gap was not nine dead mechanics, it was nine rows appended
past the line that counts them.

Worse than the wrong number: `missing`, `hollow` and the red verdict are the same snapshots, so **a
probe added down there that came back MISSING could never fail the run.**

Fixed by moving the twelve stragglers above the aggregation — same probes, same order, nothing about
them changed — and by an assertion beside the write that throws if
`works.length + missing.length !== results.length`, so the next straggler is refused by name.
