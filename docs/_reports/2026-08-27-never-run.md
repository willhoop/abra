## 5. Is the hand-maintained half the underlying defect?

**No — and a derived replacement should not be built. The defect is narrower and is demonstrated by
the very entry that was false.**

**`GATES` cannot be derived**, and this pass produced two fresh proofs rather than an argument. The
argument *is* the question: `--no-rebuild` is the difference between a read-only check and one that
rewrites artifacts its own children read; `--selftest` is the difference between 18 assertions and a
silent exit 0. Neither is a function of the filename, and no scan of the file can decide which of
several flags a suite should pass. The existing entries say the same (`--check` vs `--selftest` on
`quarantine.js`, argued in the file). Deriving this list would be **narrowing a detector to make a red
go away**, in the costume of automation.

**What is actually broken is that the exemption REASONS are unaudited prose.** The lists already audit
their own *membership* — `staleExemption` fails by name when an entry stops tripping the detector or
its file disappears, and that mechanism is sound and is what found the never-run file in the first
place. **Nothing audits the CLAIMS inside a reason string.** So:

- a reason may assert *"nothing has ever run it"* while a discovered test spawns it — **it did**, for a
  day, and only because someone ran a grep did it surface;
- a reason may assert *"already exercised by X"* where X is unwired — **8 entries now do**, honestly
  labelled, but the label is prose too.

This is the repository's signature failure wearing yet another costume: the fourteen handoffs, the ban
list of four, the auto-commit in the present tense for twelve days, `DIVISIONS.md`'s *"Four
divisions"*, CLAUDE.md's *"twenty-three files are frozen"* when `SOURCES` held twenty-five. **A number
or a claim written next to a name looks exactly as authoritative as one that was read.**

A mechanical check is *partially* available and is **deliberately not built here** rather than added
speculatively: a reason containing the literal string `tests/…js` or `engine/…js` could be required to
name a file that exists, and a reason claiming a `VERIFIED BY` runner could be checked against the
markers `register_reality.js` actually parses. That would have caught neither of this pass's two
problems, because the false claim named no file at all. **The honest conclusion is that reason strings
are prose and prose is checked by reading it, which is what this pass did to all 18.**
