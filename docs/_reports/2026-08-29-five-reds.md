## 1. `test-resolution-order.js` — the heap lead cracked it

**It was a memory ceiling in the wrapper, and the check itself has been correct the whole time.**

The file has declared `ABRA-HEAP: 6144` in its own header since 2026-08-27, and `tests/run-all.js`
derives that from the child's source and passes `--max-old-space-size`. It even detects an OOM and
prints *"RAN OUT OF HEAP. This is a memory ceiling, not a verdict about the game."*

**`tools/lownode.cmd` did not.** CLAUDE.md mandates that wrapper for every heavy run, so the command
everybody actually types ran at node's default old space — measured at **2240 MB** on this box —
and died at exit 134.

Shown red through the exact mandated path first:

```
MSYS2_ARG_CONV_EXCL='*' cmd.exe /c "tools\lownode.cmd" tests/test-resolution-order.js
  → rc 134, FATAL ERROR: Reached heap limit Allocation failed
```

and green at the declared size:

```
… "tools\lownode.cmd" --max-old-space-size=6144 tests/test-resolution-order.js
  → rc 0, 26 arms staged, 1 KNOWN-OPEN (declared, not counted), 0 failing
```

### Was it ever asserting anything? Yes, and a great deal

This is not a check that passes by asking nothing. Each of the 26 arms plays the same script through
both engines under the differential's own pin and compares the two protocol streams line for line —
nothing is typed, Showdown is the expectation. Every arm is then played a **second** time against the
same bytes with one named surgical patch that reverts exactly one fix in memory. A RED arm must agree
clean and part under its own break; a CONTROL must agree under both. The run prints eight `RED PROVEN`
arms with their parted lines and their counters, plus over-fire controls including a knob-cleared
one-field control. One arm is `KNOWN-OPEN`, declared and not counted.

### The fix, and why it is in the wrapper

`tools/lownode.cmd` now derives the heap from the script's own header, exactly as `run-all.js` does,
and never from a table. Only the first argument is inspected and only when it is a file that exists,
which keeps a user argument out of every place cmd's parser can choke on a quote or a paren. A script
with no declaration is unchanged.

**One line in that fix is the whole difference between working and silently doing nothing**, and it
was caught only by testing both spellings:

```
set "ABRAFILE=%~1"
set "ABRAFILE=%ABRAFILE:/=\%"
```

`findstr` reads a leading `/` in its file argument as a **switch**, so `findstr … tests/test-resolution-order.js`
opens no file, matches nothing, and the wrapper runs at the default heap **having reported no error at
all**. Every invocation in this repository and in CLAUDE.md is written with forward slashes. Measured:
the same file with backslashes derived `5120` correctly while the forward-slash form derived nothing.
Un-normalised, this would have been a capability that exists, runs clean and does nothing.

Verified after the change:

| arm | result |
|---|---|
| `lownode.cmd tests/test-resolution-order.js` (forward slashes, the repo convention) | **rc 0**, 26 arms, 0 failing |
| a scratch script declaring `ABRA-HEAP: 5120` | heap 5312 MB, argv `["--foo","bar baz"]` passed through intact |
| a scratch script declaring nothing | heap 2240 MB — unchanged |
| `lownode.cmd -e "…"` (no script argument) | derives nothing, runs as before |
| `lownode.cmd -e "process.exit(3)"` | **rc 3** |
| `tests/test-lownode.js` | 4 passed, 0 failed — the exit-code contract intact |

## 2. `test-engine-diff.js` — an exit code that could never have been green

`rc 3` is not this file's. It is `engine/publish_guard.js`:

```
*** PUBLISH REFUSED — the damage differential (engine-diff.json)
this run measured compared=150; data/engine-diff.json holds 6000
```

`--n` defaults to **150** and the published artifact holds **6,000**, so the guard refuses the shrink,
writes to `data/verification/` so nothing is lost, and sets `process.exitCode = 3` because a run that
did not publish what its own output describes must not read as a pass. That is correct.

**It is correct and it made the check permanently red.** `tests/run-all.js` discovers this file by the
`tests/test-*.js` glob and had no `EXTRA` row for it, so every suite run took the 150-row default and
was refused. **No engine state could have made it green.**

Two further things measured while here, both worth knowing:

- **The damage differential never sets an exit code at all.** The only three `process.exitCode = 1`
  sites are the accuracy, accuracy-modifier and substitute-bypass conformance sections. `disagreed`
  is published to the artifact and read by `engine/quarantine.js`; it is not this file's verdict. So
  "exits 3 while reporting `disagreed 0`" understates it — `disagreed` was never wired to the exit
  code in either direction.
- `data/engine-diff.json` was **not** touched by any run in this pass (mtime unchanged at
  `2026-08-29 02:49:53`), and `data/published-samples.json` is unmodified.

### The repair

`--out <file>` — the mitigation ROADMAP #257's row asked for and which `publish_guard.js`'s own header
records as never having existed (*"there is no `--write` flag to omit and no `--out` to pass"*). It
names where the run's artifact goes, the guard is not consulted, and the exit code is left to the
three conformance sections. **It refuses any path outside `data/verification/`**, so the flag cannot
become the #257 defect with a switch on it, and the file still carries a `NOT_PUBLISHED` block naming
why. `run-all.js` gets an `EXTRA` row, on the same reasoning as `generated_audit.js --no-rebuild`:
without it the suite rewrites a published artifact its own children read.

Shown red on a deliberate break before being trusted — with `--out` in force and one conformance
verdict forced true, the run exits **1**. The break was reverted and the file restored from a copy.

| arm | result |
|---|---|
| no `--out` (unchanged behaviour) | rc **3**, publish refused, artifact untouched |
| `--out data/verification/engine-diff.suite.json` | rc **0**; `disagreed 0`, all three conformance sections clean |
| `--out data/engine-diff.json` | rc **2**, refused by name |
| `--out …` with a conformance verdict deliberately forced | rc **1** |
| `run-all.js --list` | `RUN tests/test-engine-diff.js --out data/verification/engine-diff.suite.json` |

## 3. `probe_shield_refusal_line.js` — the ruler, and its own printout refuted its diagnosis

13 arms, 1 failing, and the failing arm was `twave-shield` — a **control**, whose streams agreed
clean AND under the knob. The engine was right.

The verdict logic was:

```js
const want = c.kind === 'red' ? 1 : 0;
const knobOk = clean.restored === 0 && brk.restored === 1 && nClean === want && nBrk === 0;
```

A blanket rule that every control announces the shield refusal **zero** times. True of the four
controls whose shield is absent or cleared. **False of `twave-shield`, which is a control with a
shield that really does refuse and that the `status` branch has announced correctly since WIRE 130** —
its own `what` string says exactly that. It read `clean=1 knob=1` against a demanded `0, 0`.

**And the printed diagnosis was refuted two fields to its left.** The line said
`<-- FAIL, the knob did not reach the driver's module` while printing
`MEDFAILS stamp clean=0 knob=1` — which is the knob loading. A wrong diagnosis costs more than none:
it sends the next reader at the module loader instead of at the expectation, which is where this sat.

### The repair

The pair is declared per arm — `announced: [clean, knob]` — and the default only fills it in
(`red → [1,0]`, `control → [0,0]`), so every other arm asserts exactly what it asserted before.
`twave-shield` declares `[1, 1]`, and that is a stronger claim than an exemption: `clean` must be 1
because a 0 would mean the already-correct site had gone quiet, and `knob` must be 1 because the
revert knob owns the seven repaired sites and not this one — if the knob ever moved this counter, the
fix had reached a site it was never meant to touch. The `<-- FAIL` diagnosis is now derived from which
clause actually failed.

Result: **13 arms staged, 0 failing, rc 0.** Shown red on a deliberate break first — re-declaring
`twave-shield` as `[1, 0]` fails with `<-- FAIL: knob announce is 1, declared 0`. Reverted.

## 4. `probe_random_target_address.js` — `sd=61 sites=62`

The file wrapped `ARM.random`/`ARM.chance`, pushed a stack site per call, and asserted
`sd.length === SITES.length`, exiting **2** on a mismatch with the message *"this file's bookkeeping
is off and nothing below is readable."*

**The bookkeeping was off and the engine was not.** `engine/game_differential.js:1349`:

```js
if (n !== undefined && MIDW.cat !== 'dmg' && !MID_RANGE_LIVE) { MID_RANGE_PINNED++; return m; }
```

The two-argument **range** form outside `getDamage` is pinned to `m` and returns before `midDraw` —
and its own comment says *"it consumes NO shared address."* So one-address-per-call was never true.

Measured before repairing, over 40 pinned games: **7 games mismatched**, and every call that produced
no address was the two-argument form — `random(0,2)` ×4, `random(1,3)` ×2, `random(2,6)` ×2,
`random(2,4)` ×1. Not one scalar or `chance` call was ever missing.

### The repair

A site is recorded only when the address log actually grew, and that is **derived** from the log
rather than from a rule about which forms are pinned. `MID_RANGE_LIVE` and the `dmg` exclusion have
both moved once already this month; a copied predicate would go stale silently and re-open this defect
one register row later. The length assertion is **kept** — it now means something narrower and worse
(a draw took an address without passing through the wrappers, so every stack would be attributed to
the wrong draw).

Result: **rc 0, no mismatch in any game**, at 176 games and again at 777.

### The second defect, found by fixing the first — FILED as #533

With the file running to completion for the first time since 2026-08-27, **clauses 2–4 read `0 of 0`**.

That is not the repair narrowing the instrument, and it was settled by measurement rather than
argument. Over 300 pinned games the `Side.randomFoe ← BattleActions.runMove` call site fires **103
times** on the real stack, and the address categories are:

```
  1174  any (addressed)      944  acc      942  dmg      941  crit
   394  tgtla                250  sec      131  any (blank)      104  tgt (addressed)
```

The draw is all 104 of `tgt`, and **zero** of it is in the blank `any` bucket clauses 2–4 read.
**ROADMAP #478's engine-side half has landed** — `midDraw` now addresses `tgt`/`tgtla` from
`MIDW.tgtMove`/`MIDW.tgtAtt` instead of leaving them blank — and the draw moved out of the bucket the
clauses scan. Clause 4 is the negative control, so it is a control that cannot fail against a clause
that cannot see anything.

Clause 1 — the file's published conclusion — is unaffected and reproduces: 6 call sites in the blank
bucket, 105 of 212 base addresses (49.5%) drawn more than once, deepest 4. **Nothing is retracted.**

Not repaired in this pass, deliberately: re-aiming clauses 2–4 changes what the probe measures, and
its 2026-08-27 numbers are quoted in a report and in #478, so a re-aim is a re-measurement and needs
its own pass. **A zero that means "nothing was asked" reads exactly like a zero that means "nothing
was wrong"**, which is why it is a row and not a footnote.

## 5. `probe_instruct_shield.js` — a real engine defect. FILED as ROADMAP #532, not fixed

5 arms, 3 failing, and the three failing arms are the three declared-red arms. Both controls held,
including the one that rules out the obvious wrong fix.

**Instruct's `instruct` branch in this engine checks Good as Gold, Instruct's own `refuses` list,
`_charging` and `_recharge`, and calls `shieldRefuses` nowhere.** It is a missing caller, not a
misplaced announcement, and the consequence is `acts.splice(actIdx+1, 0, _entry)` — a second click in
a turn the authority never gave one to. `MEDSEEN.instructRepeat` reads **1** on each red arm, so "the
streams parted" and "a second action happened" are two observations rather than one.

All three part at reduced line 12 with the same pair:

```
showdown  |-activate|p1a: <target>|move: Protect
medicham  |-singleturn|p1a: <target>|move: Instruct|[of] p2a: Oranguru
```

Staged through three members of the family — Protect (149,746 uses), Spiky Shield (2,103), Baneful
Bunker (1,746), membership and `blocksStatus` read off `shieldsUser` in the release's own
`data/tags.json` — so the result cannot be about the move `protect`. The King's Shield control is the
one that matters: it is the only member with `blocksStatus === false`, so the shield does not refuse
Instruct at all and the authority fails it for its own `failinstruct` flag. A patch that announced
`-activate` whenever `t.protect` was true would pass all three reds and **break that control**.

**Board-material without argument: the shielded body takes a turn it was never given.**

Not fixed, per `docs/DIVISIONS.md` — this is ENGINE's file and other batches are moving it.

### It had no runner, and now it does

`VERIFIED BY` needs a command `engine/register_reality.js` will actually execute. This probe used to
exit **2** unless handed `--release <id>`, for a reason its header states and which was **dated** —
*"the tree it would freeze is being edited by another agent"*, true on 2026-08-27, not a property of
the check. A marker naming a literal release id strands the moment the id ages out (LESSONS §12), so
the three red arms could only ever have been **debt** in the register.

It now takes the `tests/_live_release.js` route its sibling `probe_shield_refusal_line.js` already
used: a bare run freezes the **live** tree into a throwaway store under the OS temp directory.
Verified — `git status` shows `data/releases/` and `data/engine-release.json` untouched, and the cut
returned `124f5aa8c8bd` because an identical tree yields an identical id.

**The marker shape was checked, not assumed**, because this repo has already paid for it once
(ROADMAP #521). `register_reality.js`'s `SAFE` regex is `/^node\s+…/` — an `SHOWDOWN_PATH=…` prefix
fails it, and a flag taking a separate-token value (`--release <id>`) fails it too. The marker is
therefore exactly `node tests/probe_instruct_shield.js`, which was run with **no env var at all** and
exits 1 (`engine/showdown_path.js` resolves the sibling checkout). Its first draft was also bolded
across the colon — `**VERIFIED BY**:` — which `MARKER` cannot see; caught by parsing the row with
`register_reality.js`'s own regexes before finishing.

## The generalisation: how many other scripts die the same way and are read as "ran"

### The declaration is honoured in one place out of eighty

**79 files in this repository spawn a node child** (`spawnSync` / `execFileSync` / `execSync`).
**Exactly one — `tests/run-all.js` — derives the child's heap from the child's own source.** Two
others hard-code a flag for their own children (`engine/argmax_paired.js`,
`build/strong_player_baseline.js`). Every other spawner, and `tools/lownode.cmd` until this pass, runs
its children at node's default.

### Today's actual exposure is small, and that is measured, not assumed

Only **two** files declare `ABRA-HEAP`:

| file | declares | at the default (2240 MB) |
|---|---|---|
| `tests/test-resolution-order.js` | 6144 | **dies, exit 134** — this was red #1 |
| `tests/probe_endturn_clock_order.js` | 4096 | **passes** — measured today, 7 arms, 0 failing, rc 0 |

`engine/register_reality.js` execFileSyncs markers with `process.execPath` and no heap handling at
all, and two ROADMAP rows are `VERIFIED BY: node -r ./tests/_live_release.js
tests/probe_endturn_clock_order.js`. Those two are **not** bitten today — the probe passes at the
default — but they are one arm away from being, and register_reality would file the SIGABRT as a
failed verification, i.e. a memory ceiling recorded as a broken end-turn clock. That is the same class
as #1 and it is not fixed here, because nothing is currently failing and a speculative fix to

### And "a generator that dies looks exactly like one that ran" is verifiable from the source

Nothing on disk records that the regeneration did not happen. Nothing in this repository spawns

**`tag_dex.js` was NOT run.** It rewrites `data/tags.json`, which is a frozen release input, and
ROADMAP #529 already records that a no-op regeneration produces a 703-line diff of live-store usage
