## The headline number, and why it is written as a rise rather than a regression

The brief's instruction was the hard part of this pass: **board-material 50 → 53 of 961 is worse and
is the fix working.** All eight documents say it in that order — the number first, the mechanism
second — and each states the same three pieces of evidence, because the sentence is only worth
anything if the attribution is narrow:

- the direction was written down BEFORE the run, in `data/verification/2026-09-04-M6-address-prediction.json`,
  as neutral-to-slightly-worse, and **protocol missed the stated band by one**, which is stated and
  not smoothed;
- **exactly one divergence class moved** — `-damage field` 18 → 22 — and nothing else in the run
  changed by a single game;
- **eight of eight moved causes carry `[from]confusion`.**

The defect's true size is **14 games**; four had been hidden by a coin landing the same way on both
engines, and correcting the address removed the coincidence. Each document also carries the framing
the brief asked for: the number rose because the instrument can see more, which is the same shape as
the coverage-driver swap that took the gate off its false all-clear.

## The citation rule, measured before writing rather than after

`citationsIn()` matches `data/<name>.json` only — a path with a second slash is not a citation, so
naming `data/verification/fix-batch-M6-sidesel.json` or the prediction file does not put a block
under rule 3b(b). Naming `data/game-differential.json` does. So every figure planned for a cited
block was probed against that artifact's number set with `docs_scan.artifactHas` **before** the text
was written: 53, 77, 154, 150, 168, 961, 14, 18, 22, 80, 84, 124, 115, 58, 73, 216, 27 are all
present; **829, 632, 908, 210 and 26471 are not**, and were kept out of any cited block. `26471`
is written only as `engine/medicham2-browser.js:26471` inside backticks, which `figuresIn` strips —
it is the one figure in this pass with no artifact behind it anywhere.
