## 2. DO THEY SHARE A ROOT? YES, AND HERE IS HOW I KNOW

Not "it looks likely". Four things are identical, and one of them is a protocol line rather than an
inference:

1. **The same divergence class and cause string**: `unrelated event mismatch :: |-damage|p1a|H/H <> |-crit|p1a`.
2. **The same position in the click**: arrival 2 of 2, after both engines had agreed on
   `|-resisted|` for that arrival.
3. **The same move and the same attacker slot**: `p2b: Aerodactyl`, `Dual Wingbeat`.
4. **The disagreement is a `|-crit|` LINE that one engine emits and the other does not** — an
   announcement, not a number I had to reverse-engineer.

Hit 1 agreed to the exact HP in both games, which rules out anything upstream of the crit: base
power, stats, the type chart, the spread multiplier, the damage index.

**The mega-arithmetic hypothesis is RULED OUT, by evidence rather than by magnitude.** Glimmora is
`Glimmora-Mega` and Tyranitar is not a mega at all, so a mega-only stat defect cannot produce both;
and hit 1 of the Glimmora game agreed to the point, which a wrong mega stat line could not.

## THE PATCH, NOT APPLIED

**File:** `engine/medicham2-browser.js` only. Nothing in `board.js`, `magnemite.js` or `engine-data.js`.

**Function:** the damage step of the battle loop (the block containing `const _price=(isCrit)=>dmgRange(...)`
through the packet-application loop), plus one read in the arrival emit loop.

Three coordinated edits. The pricing call `_price()` consumes no die, so calling it twice is free.

**(A) Snapshot the NON-CRIT packet bands before the crit re-price overwrites them.**
Immediately after `let d=_price(false);` (anchor `const _price=(isCrit)=>dmgRange`):

```js
/* the plain bands, kept, because _price(true) refills _hitCtx.packets in place */
const _pkPlain = Array.isArray(_hitCtx.packets)
  ? _hitCtx.packets.map(p => ({ min: p.min, max: p.max, band: p.band ? p.band.slice() : null }))
  : null;
```

**(B) Draw the crit die once per ARRIVAL, not once per click.**
At anchor `{const _cc=critChance(a.move.id,m,suppressedAbility(m,tg),tg),_cr=_R.crit();` — replace the
single `_cr` with a vector sized by the arrival count, and call `_price(true)` once to get the crit
bands:

```js
const _nArr = (_pkPlain && _pkPlain.length > 1) ? _pkPlain.length : 1;
const _crits = [];
for (let i = 0; i < _nArr; i++) {
  const _cri = _R.crit();                       // unconditional, exactly as the single draw was
  _crits.push((_cc >= 1) || (_cc > 0 && _cc < 1 && _cri < _cc));
}
MEDSEEN.critDrawsPerArrival += _nArr;           // a capability that cannot prove it ran is broken
const _pkCrit = (_crits.some(Boolean) && _cc > 0 && _cc < 1) ? (() => {
  const _dc = _price(true);
  return { d: _dc, pk: Array.isArray(_hitCtx.packets)
    ? _hitCtx.packets.map(p => ({ min: p.min, max: p.max, band: p.band ? p.band.slice() : null })) : null };
})() : null;
```

`_cc >= 1` (Flower Trick, Storm Throw, Frost Breath) keeps its existing skip — `dmgRange` has already
folded that 1.5 into the range and re-pricing would apply it twice. The `_cc > 0 && _cc < 1` guard is
the existing one, unchanged.

**(C) Select per arrival, in the two places that read the single boolean.**

- At anchor `const _au=(i===0)?_u:_R.dmg();` — read the band from `_crits[i] ? _pkCrit.pk[i].band : _pkPlain[i].band`
  instead of from the single `_pks[i].band`, and set `_rmin` to the matching range's min.
- At anchor `if(TR){TR.eff(tg,R.effShow);if(R.crit)TR.crit(tg);}` (the packet emit loop) — read
  `_crits[i]` instead of `R.crit`.
- The single-packet path (`_nArr === 1`) is byte-identical to today: one draw, `_crits[0]`.

**Two things the patch must also do, or it is not finished:**

1. **A RESTORE KNOB, so the probe can be shown RED rather than asserted.** `MEDI_CRIT_ONCE_PER_CLICK=1`
   pins `_nArr` to 1 and reuses `_crits[0]` for every arrival — the same shape as the existing
   `MEDI_MULTIHIT_ONE_INDEX` / `MULTIHIT_ONE_INDEX_RESTORED`, with the counter published so a fix that
   silently stops firing does not look like one that works.
2. **`R.crit` STILL HAS ONE DOWNSTREAM READER AND THAT IS A JUDGEMENT CALL, NOT A DETAIL.**
   `engine/medicham2-browser.js` anchor `const _bHit=_buff?{crit:R.crit,...` feeds `buffsHolderOnHit`
   (Anger Point). The authority raises that per HIT with that hit's own crit. **`_crits.some(Boolean)`
   is the behaviour-preserving choice for Anger Point** (any crit maxes Attack) and matches the
   authority's observable outcome for the abilities in this format; `getMoveHitData(move).crit` after
   the volley is the LAST hit's value, so the two differ only for a reaction that reads the flag once
   after the volley. **Set `R.crit = _crits.some(Boolean)`, count it, and file the per-hit reaction
   pass as a separate row** — do not bundle it. `_stepEffects` is still wrapped once per move here.

**Not bundled, named so it is not rediscovered:** the arrival loop computes all N packets before the
`tg.curHP<=0` break, so on a KO'd volley this engine draws more `dmg` (and now `crit`) than the
authority does. That is pre-existing, it is the same shape for both dice, and under an **event-
addressed** die a draw only one engine makes is harmless by construction — `game_differential.js`'s
middle-arm header states exactly that. Draw ORDER likewise does not matter: each `_R.crit()` gets
nth 0..N-1 at the same address the authority's N `randomChance(1,24)` calls get.
