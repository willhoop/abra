## Line endings — measured per file, not assumed

The claim that `docs/ENGINE.md` is LF-only was checked rather than inherited, and the honest answer
is that it depends on when you look:

| file | on disk at write time |
|---|---|
| the six version-headed docs, `docs/MEASURE.md` | CRLF, every line |
| `docs/ENGINE.md` | **LF, every line** |

`core.autocrlf=true`, so the repo side is LF for all of them. `docs/ENGINE.md` is LF in the WORKING
COPY right now because the ENGINE agent rewrote it during this session — `git diff` prints
*"LF will be replaced by CRLF the next time Git touches it"* for that file and for no other. The
insertion tool detects the ending per file and joins with what it found, so every file still matches
its own disk state; no file's endings were converted. A `grep -c $'\r$'` reading was wrong here and
was discarded in favour of counting `\r\n` against `\n` directly.
