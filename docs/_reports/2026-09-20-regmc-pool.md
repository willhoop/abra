## The predicate, exactly

```
KEEP a game      IF  openSheet === true AND both sheets are present
EXCLUDE it       IF  date < 2026-09-14        (UTC, derived from the replay's uploadtime)
                 AND an item with id 'ejectbutton' is declared on EITHER sheet
```

`date` is UTC derived from `uploadtime` — READ: `engine/durable-ingest.js:38` and `:517`. The item id
is READ from the diff of Showdown commit `aa6d5f0856` against
`data/mods/champions/items.ts`, where the added key is `ejectbutton`; its canonical name
(`Eject Button`) and `isNonstandard: null` are DERIVED from `Dex.forFormat('gen9championsvgc2026regmc')`
on the M-C checkout at each run.

The commit is authored **2026-09-13 20:13 UTC** and the deploy time to the live server is unknown,
hence a full day of margin on the boundary rather than an hour.

## Why the conjunction, measured rather than argued

A game in which the item never appears cannot have been affected by a change to that item. On the bo3
stream, **8,352 games predate the boundary and 1,516 carry the item at any date, and only 335 are
both.** A date-only cut discards 8,352 games to guard against 335 — **25 times the damage**.

**Both sheets are scanned, not the holder's.** Under open sheets every item on the field was declared
by one of the two players, so a transferred item is still visible on somebody's sheet. Re-derived here
rather than taken from the brief: within the in-scope population of both stores, **0 games name the
item anywhere in the record without it appearing on a sheet.** There is no hidden case.

**And the raw ladder store shows what closed sheets cost.** It names the item in 1,047 games while only
83 in-scope games declare it. The other 964 are closed-sheet games where nothing is declared at all —
the conjunction cannot even be evaluated there. That is evidence for the open-sheet scope rule rather
than against it, and it is the only place the two stores behaved differently.

which filters a game**.

2. **Every kept sheet was validated** as a diagnostic on the store: **49,664 sides, 47,862 accepted,

**A rejection in (2) is a claim about the RECONSTRUCTION, not about the team.** The store records no

zero-investment clause fires only when the nature is `Serious` (READ:

the store schema and is counted apart from everything else. **Zero sheets failed for any other reason**,
which is the number worth keeping: the store's declared sheets are validator-legal M-C teams.

## How the torn read was avoided

The collector appends to both source stores hourly and commits them, and this repo has already produced
one plausible, well-formed, completely fictitious answer by reading a file mid-write.

- The run executed inside a git worktree pinned at `2b25bd0f`, so both `.gz` stores were read as
  **tracked blobs at a fixed commit**, not as live files. `git status --porcelain data` was empty
  before and after, so the checkout bytes are the committed bytes.
- The receipt stamps the **sha256, byte count, mtime and line count of the path the run actually
  opened** — ROADMAP #547, the pool cache that named the live store during a pinned run and was
  verified correctly for the wrong reason. Nothing here is digested from a canonical path.
- The whole cut was re-run and produced a byte-identical pool digest, which a moving source could not
  have done.

Worth noting for whoever reads `docs/REGMC.md` next: its live readout block says `23,554` bo3 and
`32,918` ladder games "at 2026-09-20 20:50", and the tracked blobs at `2b25bd0f` hold **23,808** and
**33,275**. That page says to re-derive rather than quote it, and this is why.

## Contract notes for the next run

- The basenames **must** be `games.bo3.jsonl` and `games.ots.jsonl`: `diff_swarm.loadTeams` opens
  exactly those inside a `--team-store` directory (`engine/diff_swarm.js`, the `for (const f of
  ['data/games.bo3.jsonl', 'data/games.ots.jsonl'])` loops). The directory name is free; the basenames
  are not.
- `data/diff-team-pool.json` is a **single shared cache** keyed on size+mtime of those two basenames.
  Alternating between the M-B and M-C pools will therefore force a rebuild each way — correct, but it
  costs ~40 s and prints `pool cache MISS`, which is expected rather than a symptom.
- The `.jsonl` files are untracked (`.gitignore`, new rule beside the M-B one). `games.bo3.jsonl` is
  **236 MB — over twice GitHub's hard 100 MB per-file limit**, so tracking it would fail the push, not
  a review. Tracked growth from this pass is `FROZEN.md` + `pool-receipt.json`, about 9 KB.
- The pool is a filtered copy: every kept game is written back **byte for byte** as the store held it.

## `status.js --write` MUST NOT BE RUN FROM AN AGENT WORKTREE — found the hard way, here

MEASURE's own brief ends with `node engine/status.js --write`. Run from this worktree it produced
stamps that were not merely stale but **wrong in the direction that matters**, because a worktree
holds only TRACKED files and this project's state is computed over artifacts that are deliberately
untracked (the frozen pools, `data/diff-team-pool.json`, the live stores):

| file | HEAD says | the worktree run wrote |
|---|---|---|
| `docs/WEB.md` | the live gate is **OPEN**, 0 of 10 clauses fail | **CLOSED**, 2 of 10 fail |
| `docs/MEASURE.md` | three artifacts WITHHELD on provenance | the same three `QUARANTINED` because *"MEDICHAM is not correct"* |
| `docs/OPS.md` | store heartbeats dated 2026-09-10 | `NOT DERIVED`, `last written —` |
| `docs/MEASURE.md` | provenance 229 unsafe / 15 ok | 79 unsafe / 98 ok |
| `data/provenance-stamp.json` | ratchet 179 | **178** — dropping three files that exist in the main tree |

The last row is the dangerous one: that file is a RATCHET that may shrink and may never grow, so
committing a worktree-computed shrink would leave a floor the main tree cannot get back under, and
the next honest run there would read as a regression.

All six files were reverted with `git checkout --` before anything was committed. **The restamp
belongs to the publisher, in the main checkout.** This is the same shape as every other finding in
this report: an instrument reading a tree that is not the tree the claim is about.

## Commands

```bash
node engine/cut_regmc_pool.js                 # dry run: every count, writes nothing (~90 s)
node engine/cut_regmc_pool.js --write         # cut the pool, the receipt and FROZEN.md (~240 s)
node engine/cut_regmc_pool.js --no-validate   # skip the TeamValidator pass
```

Run through `tools/lownode.cmd`. From Git Bash that means ROUTE A in the wrapper's own header —
`spawnSync('cmd.exe', ['/c', 'tools\\lownode.cmd', …])` from node — because both typed Bash forms lose
bytes before the .cmd starts. The script declares `ABRA-HEAP: 4096` in its header and the wrapper
derives it.
