## 5. THE CHECK — AND WHY `artifact_audit.js` IS NOT THE FAILURE HERE

**It caught it.** Section G of `engine/artifact_audit.js`:

```
G. THE BROWSER COPY AGAINST THE NODE ORIGINAL — generated bundles vs their sources
     10 generated bundle(s) under data/ declare a builder; 5 of those builders offer --check and are COMPARED
  GAP  data/abra-tags.js is NOT what build/build_tags_js.js would write from data/tags.json
  ...
1 GAP(S) FOUND                                                            [exit 1, 1.56s]
```

After the rebuild, the same command: `ok data/abra-tags.js is what build/build_tags_js.js would
write from data/tags.json` … `no gaps found`, exit 0. **Red then green, on real data, on the real
pair.**

**It is a property, not a named pair.** It reads `data/*.js`, matches each file's own
`GENERATED by <builder> from <source>` header, and spawns that builder's `--check`. Nothing about
`abra-tags` is written into it; a new bundle is covered the day its header says so, and the five
bundles whose builders have no `--check` are printed as uncovered on every run.

**Why it did not stop this.** Not membership, not shape — **placement**:

- The only thing that runs it is `tests/run-all.js`, which is minutes long and rare.
- Nothing runs it at the moment the drift is created (`engine/tag_dex.js` rewrites `data/tags.json`
  and neither rebuilds the copy nor warns) or at the moment it becomes permanent (the commit).
- It was in fact seen: `docs/_reports/2026-09-04-runall-triage.md` line 93 carries the row, annotated
  *"base worktree reports 3 GAPs, live reports 1 — this check got BETTER across the session."*

The other two candidate checks were examined and **neither claims this**. `tests/test-engine-diff.js`
reads `data/abra-tags.js` as its scenario source (so it built its scenarios from the stale table) and
asserts nothing about agreement. `tests/test-mechanics.js` names `data/abra-tags.js` in prose and
actually reads `data/tags.json`.

`engine/generated_audit.js` — which also covers this class — is registered in `tests/run-all.js` with
**`--no-rebuild`**, the mode that explicitly gives up rebuild-agreement and files the pair as
`UNPROVABLE`. Its own registration comment names that hole and says *"wire the rebuild half the day
something can give it a scratch tree to build into."* It is therefore not a second miss; it is a
declared gap that this instance landed in.

### What was built: the moment, not another comparison

`.githooks/pre-commit` gains one clause, placed **before** the documentation scope guard:

```sh
if command -v node >/dev/null 2>&1; then
  echo "pre-commit: generated-bundle gate (~1.6s) -- every data/*.js against the source it declares"
  if ! AA_OUT=$(node engine/artifact_audit.js 2>&1); then
    ...  exit 1
```

Placement is the load-bearing part. The guard immediately below reads

```sh
echo "$STAGED" | grep -qE '^(docs/|engine/|tests/|web/|CHANGELOG\.md|README\.md|CLAUDE\.md)' || exit 0
```

so a commit staging only `data/` never reaches anything after it. *"Regenerate the tags, commit the
data"* is the shape of all five instances, so a clause below that guard would be a check that cannot
fire on the case it was written for.

Design constraints, each answered:

- **Content, never mtime.** It re-runs the builder and compares what it would write. No timestamp is
  consulted anywhere in the path.
- **Cheap enough to run every time.** 1.56s measured; the five builder `--check`s are 1.23s of it, so
  a "bundles only" flag would have bought ~0.3s and cost an invasive edit to a registered gate. Not
  done.
- **No stamp needed.** Regenerating is cheap here, so the stronger comparison is available and the
  digest-stamp fallback the brief allowed for was not required.
- **Writes nothing.** `artifact_audit.js` contains no write call, and each builder's `--check` branch
  returns before its own `writeFileSync` (verified in `build_tags_js.js`, `build_guru_js.js`,
  `build_browser_data.js`, `build_engine_data.js`). Bundle mtimes were checked before and after.
- **No silent skip.** If `node` is absent the clause prints *"generated-bundle gate SKIPPED (this is
  a hole, not a pass)"* rather than passing quietly.

## 6. WHAT THIS DOES NOT CLOSE

- **The creation moment is still open.** `engine/tag_dex.js` is the only writer of `data/tags.json`
  and all five instances are "it ran, the copy was not rebuilt." Making it rebuild the copy in the
  same act would drop the drift window to zero. It was **not** done here because it could not be
  verified without re-running `tag_dex`, which would rewrite `data/tags.json`, strand release
  `ae608567e8a8` and void the five re-runs above. Shipping it unverified is the failure this
  repository names first.
- **`--no-verify` and `core.hooksPath`.** A commit that bypasses hooks still gets past this. The
  suite-level gate remains the backstop.
- **Five bundles are still uncovered** — `abra-meta.js`, `board-data.js`, `mag.js`, `mew.js`,
  `status.js` — their builders have no `--check`. `artifact_audit.js` prints them on every run.
