## 1. Why pushing kept failing

Cowork runs the shell in an isolated Linux VM with no access to the machine's git credentials and no
route to the account's connectors. `git push` from that shell **cannot** authenticate, regardless of
what is authorised on the account. The GitHub connector being enabled does not help, and repeatedly
asking the user to re-authorise it was wrong.

**Use Claude Code in a terminal for anything involving git.** There the shell runs on the user's own
machine with their credentials and `git push` simply works.

**The user's rule number one: do not ask them to run commands, and never take over their machine.**
Machine control was tried once and caused the damage in section 0. Do not repeat it.

## 2. What was actually achieved today (all committed locally)

### The rollout engine was wrong in eight ways, all silent

`engine/medicham2-browser.js` — fixed: random status instead of the move's status; only Fake Out
could flinch; no type or ability immunities; priority a hand-typed table of 18 moves (all 14
negative-priority moves resolved at 0, so Trick Room went at normal speed); flinch leaked into the
next turn; **Intimidate applied unconditionally with the sign reversed on Defiant/Competitive**; no
powder immunity; Prankster hit Dark types.

Measured effect: **4.35** points of P(win) on average across 120 real matchups, max 24.2, favourite
flipped in 9.2%. Tests: `tests/test-rollout-effects.js`, 39 assertions.

### The official Champions engine exists and we should switch to it

`data/mods/champions/` is in the Showdown **master** branch (not the npm package). Format
`gen9championsvgc2026regmb` is exactly ours. `engine/champions_sim.js` runs it, pinned to commit
`20ad99ffc9a5a4a4e8fb56ab04ad8e4255b3f2b4`. `engine/prior_player.js` ports our policy into it.

**With identical teams and identical policy, our engine and the official one disagree by 31.1
points.** Everything fixed today was worth 4.35. See `docs/ADR-001-use-the-champions-mod.md`,
which records all four comparison attempts including the three that were wrong.

Speed: official 29 battles/sec/core, ours 3,401. Offline batch work is fine; live browser use is not,
and is not needed — precompute tables offline and ship them.

### Five bot accounts were hiding in the data

Name-based detection missed them. The decisive signal is **team invariance**: `Carchdraw84172` played
459 games with exactly one team, 367 of them in a single day. Four of the five ran the SAME six
Pokemon in 1,446 games.

Clean games: **927 of 7,547 (12.3%)**, not the 1,941 previously believed. Definition lives in
`data/quality-filter.json`; readers are `engine/quality.js` and `engine/quality.py`, cross-checked by
`tests/test-quality.js`.

### The metagame model was literally the bot's team

`meta-usage.json` — the file CHOMP reads — had this top six:

    garchomp, whimsicott, basculegion, kingambit, charizard, sylveon

That is, in full, the bot team's six Pokemon. Corrected top six after filtering:
`garchomp, incineroar, kingambit, sinistcha, whimsicott, basculegion`. Basculegion 34.1% -> 17.9%.
`engine/analyze.js` now uses the quality filter and stamps provenance into its output.
